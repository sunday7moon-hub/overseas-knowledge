# 技能实战数据同步（防口径漂移）

把外部数据源（汇报 PPT / CSV / 调研）里的实测数据与规划指标，安全地并入已有技能。
**核心不是"写进去"，而是"只写一处 + 其余引用"**——否则下一个版本必然漂移。

## 适用时机

- 用户给出汇报/PPT/数据表，要求"同步进技能""按这个更新画像"
- 技能里的画像/阈值与最新实战数据出现差异，需要校准
- 要把规划指标（如 Q3 目标）加入技能，供后续业务指导使用

## 前置：先提取，再对齐

1. **提取数据源全文**（PPTX 用 python-pptx 递归取 shapes + tables，含 group shape）
   ```bash
   VENV=/Users/yoyo/.workbuddy/binaries/python/envs/default
   "$VENV/bin/python" -c "from pptx import Presentation; ..."
   ```
2. **读透目标技能**：`SKILL.md` 全部模块标题 + `references/` 下所有文件，标出**既有数值在哪几处**。
3. **判断插入点**：新增数据属于"历史事实"还是"计划目标"（决定放哪个文件，见下）。

## 第 1 步 · 拆「双真相源」（关键）

凡技能同时含**实测数据**和**规划指标**，必须拆成两个 references 文件，**同类问题只归一文件**：

| 文件 | 管什么 | 触发问法 |
|---|---|---|
| `references/practice-baseline-<期>.md` | **历史事实**：统计口径、漏斗、分布、损耗、对标 | "做过什么 / 数据多少 / 哪类客户转化好" |
| `references/q3-plan-roadmap.md` | **计划目标**：断点、动作、验收指标、扩展方向 | "目标是什么 / 怎么打 / 往哪扩" |

两个文件顶部都要写：
- 「**本文件是唯一真相源**，其他文件只做摘要与指针，不得复制本文件数值」
- 数据来源（文件 + 日期 + 页码）、版本号、**口径提醒**

baseline 文件必须含**「口径」小节**（统计范围/归类方式/分母定义/排除条件），否则后人无法复核。

## 第 2 步 · 主文件指针化（零数值）

`SKILL.md` **只写规则、判据、分层与指针，不写具体数值**：

- 新增/改写模块时，用**定性描述 + 「详见 X §N」**替代数字
  - ✅「工业制造规模最大但客户通过率最低 → 需强需求澄清（见 baseline §6）」
  - ❌「工业制造 82 JD、通过率 11.9%」
- **画像类更新做分层**，让结论可直接用：行业 P0/P1/P2、区域 规模核/质量核/储备、岗位 成熟/结果/潜力/不主攻
- **保留「修正记录」**：写清"原设定 → 实战修正 + 依据 §N"，否则下次会有人改回去
- Overview 处加**分流表**（哪类问题读哪个文件）+ **引用纪律**（计划值≠成果）

## 第 3 步 · 门禁自检（必跑）

```bash
# SKILL.md 应零数值残留；命中即说明被复制，需下沉到 references
grep -nE "[0-9]+ *(个)? *JD|[0-9]+\.[0-9]%|[0-9]{2,}(,[0-9]{3})* *家" <SKILL.md> \
  && echo "⚠️ 有残留" || echo "✅ 无残留数值副本"
```

> 判据：**「我要改这个值，需要动几个文件？」答案 >1 就是设计错了。**

## 第 4 步 · 下游快照同步（易漏）

技能常被复制进**专家包 / 交付件**。这些副本必须：
1. 文件头注明「本文件是快照，**权威源为技能 `references/X.md`**，技能侧更新后需同步」
2. 带**快照版本号**（随技能版本递增）
3. 副本自身**不再向下复制**（只引用，不转抄）

同步清单：专家包 `skills/*/references/*`、内置 `SKILL.md` 参考表与核心事实、Agent 档案（如新增能力要加 Workflow/路由表）、交付件 md。

## 第 5 步 · 计划类内容的表述边界（对客风险）

规划指标一旦进技能，会被用于生成对客内容，必须加约束：

- **计划值 ≠ 既有成果**：「Q3 目标 12 Offer」不得写成"已交付 12 Offer"
- **口径不得升级**：自动化「任务执行成功率」≠ 业务转化率
- **不宣称全自动**：人工质量门（需求画像/寻源策略/内审/面试/Offer）要显式列出
- 交付件里给**「可以说 / 不能说」对照表**，比一句"注意口径"更有效

## 踩坑清单

| 坑 | 表现 | 正确做法 |
|---|---|---|
| 数值被复制 | SKILL.md 复写关键数字，改一处漏一处 | 门禁 grep 兜住 |
| 计划混入成果 | Q3 目标写在"交付战绩"里 | 拆文件 + 标注「规划目标」 |
| 口径缺失 | references 只有数字没有分母/排除条件 | baseline 必有「口径」小节 |
| 修正被回滚 | 只改结论没写"原设定→修正" | 加「修正记录」表 |
| 快照反客为主 | 专家包副本被当成真相源修改 | 副本头部标权威源 + 版本号 |
| 提取漏内容 | PPTX 只读顶层 shape，表格/组合框丢失 | 递归 walk shapes + 处理 `has_table` 与 group |

## 收尾

- 技能与专家包改完，**重跑校验并重新注册/打包**（专家包：validate → register → package）
- 工作日志记**事件**（做了什么、改了哪些文件）；用户级 MEMORY 记**规则**（双真相源分流 + 门禁命令）

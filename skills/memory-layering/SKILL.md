# 项目记忆分层维护

解决两个反复出现的问题：
1. 🔴 **写不进**：`MEMORY.md` 撞硬上限（**实测 12KB**）→ 被注入截断，新增内容静默丢失。
2. 🔴 **找不着**：同一主题散在主文件 + 明细层 + 多份日志里，**并行维护必然漂移**（改了一处，另两处变成过时的真相源）。

> ⭐ 核心判断：**记忆是三份，但每个事实只活在一个地方。**

---

## 一、三层结构与读序

| 层 | 文件 | 是否自动注入 | 放什么 | 体积上限 |
|---|---|:--:|---|---|
| 主文件 | `MEMORY.md` | ✅ **自动注入** | 只留 **红线、判断、指针** | 12KB **硬**（超了截断） |
| 专题 | `MEMORY-<主题>.md` | ❌ 按需读 | 一个主题的**全量**：索引 / 事实 / 规格 / 待办 | 无（建议 < 30KB） |
| 明细 | `MEMORY-details.md` | ❌ 按需读 | **非专题类**明细：凭据、命令、月度表、坑位 | 无 |

读序：**`MEMORY.md`（自动）→ 专题（若相关）→ 明细（若需具体数字）**。
三份文件的**头部必须互相写明读序与归属**，否则下次一定读错。

---

## 二、拆专题六步法

1. **盘点**：`grep -n "^## "` 三份文件 + 列出日志，把所有涉及该主题的段落位置列出来（本项目实测散在 **7 处**）。
2. **定归属边界**：一句话写清专题范围（"凡是 X 相关，先读这份"），并明确**哪些内容留在主文件**（红线必须留 —— 它需要随时可见）。
3. **写专题文件**，节结构**按「找得到」优先排序**：
   `0 速览` → `1 ⭐索引` → `2 事实底账` → `3 主体内容` → `4 红线` → `5 硬规格` → `6 待办/待拍板` → `7 方法论指针` → `8 工作方式` → `9 校验清单`
4. **主文件改指针**：把该主题的长段落换成「**一行指针 + 必须留在注入层的红线**」。指针要**点名节号**（"待拍板 11 项 → 见专题 §8"），否则读者还得自己翻。
5. **明细层改指针**：对应章节换成「指针 + **只在这里的原始证据**」（DOM 片段、路由清单、实测数字）。**不是全删** —— 独一无二的证据要留。
6. **头部三处同步**读序说明；写日志记录本次拆分（动机 / 做法 / 体积变化 / 索引状态）。

---

## 三、三条设计原则

### ① 红线上浮，细节下沉
判断某条内容留主文件还是下沉，只看一问：**「这条如果被截断，会不会直接导致返工或事故？」**
- 会 → 留主文件（红线 / 强制约定 / 安全项 / 不可逆操作禁令）
- 不会 → 下沉到专题（索引、规格数值、清单、工作方式）

### ② 一份内容只活在一个地方
同一事实出现两处 = 迟早漂移。**迁移时同步删源**，只在目标处保留。
⚠️ 反例：把主文件、专题、明细三处都留着"以防万一" → 下次改一处，另两处静默过期。

### ③ 索引必须带**状态列**
交付物索引只列文件名是不够的 —— 一定存在"已被取代但文件还在目录里"的情况。
状态列取值固定为：`✅ 现行` / `🟡 部分过时（写明哪部分）` / `⚠️ 前提已废` / `已被取代` / `前身（别用）`。
⭐ **不标状态的索引，下次一定拿错文件。**

## 四、⚠️ 实测坑位

1. 🔴 **字符数 ≠ 字节数** —— `len(s)` 是**字符**，中文 UTF-8 是 **3 字节/字符**。用 `len(s)` 判断"还剩多少空间"会把 12KB 上限误判成 36KB。
   **正确做法：一律 `os.path.getsize(p)` 或 `len(s.encode())`。**（本项目实测：`len(s)` 报 21557，实际 36398 字节，差点得出"还能塞很多"的错误结论。）
2. 🔴 **改含反引号 / `$` / `<` 的文本，别用未加引号的 heredoc** —— 会被 shell 当命令替换/重定向执行，**结果是把文件写坏**。
   **正确做法：用 Write 工具写 `.py` 到 `/tmp` 再执行。**
3. ⚠️ **按标题切片做块替换**（`s[s.index(头A):s.index(头B)]`）比逐条 Edit 更稳，但**替换块里复用了同一个标题**时，"残留检查"会误报为"仍在" → 检查应看**正文内容**而非标题是否存在。
4. ⚠️ **拆完必须回头核对下游不一致**：日志里写的文件名、交付物实际文件名、标题名三者常不一致（本项目实测日志写「站点改造需求清单」而磁盘文件名仍是「UI改造需求清单」）→ 在专题文件里显式标注这个差异。
5. ⚠️ **指针是双向的**：只在新文件里写"我是 X 的入口"不够，**主文件与明细层都必须反过来指向它**，否则从注入层进来的读者根本不知道有这份文件。

---

## 五、校验清单（拆分完必跑）

```bash
cd <项目>/.workbuddy/memory
wc -c MEMORY.md MEMORY-details.md MEMORY-<主题>.md   # ① 主文件必须 < 12288
grep -c "MEMORY-<主题>" MEMORY.md MEMORY-details.md  # ② 指针双向，两份都应 > 0
grep -n "^## " MEMORY-<主题>.md                      # ③ 节结构完整
grep -n "^## " MEMORY-details.md                     # ④ 该主题章节已改为指针
```
再人工过一遍：**主文件里该主题只剩红线与指针**（没有大段细节残留）、**专题里没有指向旧位置的失效指引**。

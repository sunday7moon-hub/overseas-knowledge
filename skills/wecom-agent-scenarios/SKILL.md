# 企微 Agent 场景机会评估

把「业务场景 → 企微能否承载 → 值不值得做」沉淀成可复用流程。核心资产是**企微 AI 开放能力的权威边界**与**三维打分模型**。

## 何时使用

- 用户问「企微上还能做什么 Agent / 还能做哪些场景」
- 用户给一个业务场景，问「这个能不能 agent 化 / 企微支不支持」
- 用户问「哪些场景对获客有帮助 / 平台愿不愿意吸纳」
- 需要输出「场景清单 + 优先级 + 立项建议」
- 出海招聘 / 海外 HR / EOR / 薪酬 / 合规类场景的 Agent 化规划

## 第一步：先核对企微能力边界（不要凭印象）

### 十一项原子能力（企微 5.0.10，2026-08-18 上线，不限企业规模）

| 能力 | 可做 |
|---|---|
| 消息 | 查询机器人最近会话、向机器人所在会话发送消息 |
| 邮件 | 发送/回复邮件、检索邮件、读取正文 |
| 文档 | 创建、检索、读取内容、**编辑（仅限机器人创建的）** |
| 在线表格 | 创建、检索、读取、编辑单元格 |
| 智能表格 | 字段/记录/视图/**图表**的完整 CRUD |
| 智能文档 | 页面读取、编辑、追加内容 |
| 待办 | 创建、编辑、完成、检索、读取详情 |
| 日程 | 新建/编辑/检索/读取详情、**查询忙闲**、**推荐共同空闲时段** |
| 会议 | 新建/编辑/检索/读取详情与**纪要正文**、查询会议室、**拉取会议转写** |
| 微盘 | 上传、检索、下载 |
| 通讯录 | 搜索成员、获取成员基础信息 |

接入方式：**CLI**（`npx skills add WecomTeam/wecom-unified -y -g`）+ **MCP** 双通道。
WorkBuddy 已内置企微 CLI Skill —— 连接器里添加「企业微信」扫码即可，接入成本极低。

### 五条硬约束（决定产品形态，不可绕）

| 约束 | 数值 | 设计含义 |
|---|---|---|
| 回复时效 | 必须 **3 分钟内**答完 | 长任务必须异步：先回执 → 落地资产 → 补消息通知 |
| 回复长度 | 单次最多 **2048 字节**（≈680 汉字） | 长内容必须落地成文档/表格，不能塞聊天框 |
| 授权时效 | 文档类 **7 天**到期需重新授权 | 运维负担，也是周期性触达由头 |
| 连接独占 | 同一机器人仅 **1 个**有效长连接 | 架构上不能多实例抢连 |
| 编辑边界 | 只能编辑**机器人自己创建的**文档/表格 | 对外承诺措辞必须收窄，别说「任意增删改查」 |

其他：一个应用只能发布到一个机器人；搜索类能力（邮件/文档/会议/微盘/通讯录）若企业设了审批，需管理员审批。

> ⚠️ **两个「上限」别混（2026-09-11 实测补充）**：上表的 **2048 字节**是**机器人对话回复**的上限；若走 `wecom-cli message aibot send`（CLI 主动发送）发 markdown，上限是 **20480 字节**。即：**对话内回复受 2048 约束（逼出资产化交付），主动群发长文走 CLI 通道**——本文档后面所有 2048 相关的裁剪逻辑，只针对对话回复场景，不要套到主动推送上。
>
> 主动推送的可达范围也有硬边界：智能机器人**只能发给①授权人本人 ②机器人最近有消息往来的会话**（单聊/群聊）。要推某个客户群，必须先把机器人拉进该群并产生一次会话，否则 `sessions list` 里根本不会出现该群。

## 第二步：三维打分（各 5 分，相加排优先级）

| 维度 | 打分要点 |
|---|---|
| **企微适配** | 用企微原生能力是否顺手？有没有独有优势（如「推荐共同空闲时段」「会议纪要拉取」「企微待办」是外部工具做不到的） |
| **获客帮助** | 能否让客户想起我们？能否暴露真实需求？能否自然转人工？ |
| **资产就绪** | 现有数据/内容能否直接支撑。**低于 4 分必须标「需先补数据」，不能上线** |

> 红线：资产就绪 < 4 的场景（如费率、工签规则、薪酬基准）**先补数据再上**，否则 Agent 查出来是空的或错的。

## 第三步：两条反向设计原则（本方法论的精华）

### 原则 1：2048 字节逼出「资产化交付」

聊天框装不下报告 → Agent 必须把结论落到**文档/表格/智能表格/待办/日程**。
结果：**每轮对话都在客户企业里种一个资产**（而非会被刷掉的聊天记录）。资产越积越多，替换成本越高。

### 原则 2：「待办 + 日程」是最强的主动触达武器

竞品工具（Deel / Knit / 1EOR 等）都是**客户主动来查** —— 因为它们没有客户的日历。
但待办/日程让 Agent 能名正言顺地周期性主动找客户：签证到期、合同续签、试用期到期、发薪日、各国合规申报节点。
这类钩子**强需求 + 周期性 + 不可替代**，且竞品做不到。

其他两条辅助洞察：
- **会议纪要 = 需求发现器**：面试会/评审会纪要里藏着招聘进度与卡点信号，且完全合规（客户自己的会议）
- **群聊 @机器人 = 团队基础设施**：一个人用是工具，一个团队用是流程，组织级渗透

## 第四步：平台吸纳倾向判断

| 平台欢迎 ✅ | 平台不欢迎 ❌ |
|---|---|
| 帮团队把活干完（官方三示例：文档一键读改写、会议纪要+待办派发、表格分析+群内汇报） | 对外群发、营销轰炸 |
| 在企业授权范围内读写企业自有数据 | 爬取外部数据、越权访问 |
| 加入 Agent 生态（官方点名 WorkBuddy / Codex / DeepSeek Harness / Kimi Work / MiniMax Code / 企业自研） | 绕过审批、钻权限空子 |

> **形态结论：Agent 要长得像「帮 HR 干活的同事」，不是「卖服务的销售」。** 销售动作藏在工具后面。

## 第五步：Agent 场景半径决策（一个 Agent 装多少场景）

**结论：对外一个身份，对内按岗位拆。一个 Agent = 一个岗位 = 3 个技能（下限 3，上限 5）。**

三条依据（都已验证）：
- **自有验证**：`yoyo-agent-swarm/references/job-descriptions.md` 4 份岗位说明书，每份职责均为 **3 条**
- **QoderWake**：10 个预设岗位支撑约 200 万次任务 → 阿里的做法是**按岗位封装，不按场景封装**
- **Accio 经验**：每个 Agent 只挂 3-5 个 skill，配多了会散

### 用「授权面」切分 Agent，而不是用「功能」（企微特有）

企微 11 项能力**需成员逐项授权**，文档类 7 天到期 —— 授权面就是天然的 Agent 边界。

| 级 | 需客户开启的能力 | 可承载场景 | 冷启动 |
|:--:|---|---|:--:|
| 1 | 消息 + 文档 | 法规监控预警 · 合规自检 · 合规 JD 生成 | 最低 → **首发** |
| 2 | + 在线表格 + 待办 | 候选人管道 · 入职清单 · 月度发薪提醒 | 中 |
| 3 | + 日程 + 会议 + 通讯录 + 微盘 | 跨时区面试调度 · 会议纪要派发 · 到期提醒中心 | 高 |

> 首发只踩第 1 级：授权最轻、资产最成熟（法规库 576 条 / 71 国）、平台最欢迎（工具不像销售）、需求最普适。

### 拆 Agent 的三个触发条件（满足 2 条即拆）

1. **需要给同一个 Agent 追加新权限** → 拆（授权面是切分依据）
2. **出现不同的使用者**（HR → 财务 / 法务 / 业务负责人）
3. **出现不同的触发时机**（按需提问 → 每月固定 / 事件驱动）

### 对外 / 对内必须分开（最重要的区分）

| | 对外（客户 + 平台） | 对内（产品架构） |
|---|---|---|
| 粒度 | **一个身份、一个名字** | 按岗位拆成 N 个 Agent |
| 原因 | 阿里教训：Qoder / QoderWork / 千问办公并存，连内部员工都要分辨谁是谁 | 同 `yoyo-agent-swarm` 的 A1–A15 模式：一个总管 + 专职岗位 |
| 客户感知 | 「我找的是一个人」 | 不暴露编排层 |

> 常见误区：把「产品排期可以多条线并行」和「对外口径只讲一个」混为一谈。**做的可以多，讲的要少。**

### 数量红线

- **< 3 个场景**：撑不起一个「岗位」，客户觉得是个小工具
- **3 个**：甜点区 —— 够构成完整职责闭环
- **> 5 个场景**：人设开始崩（一个「人」不可能既懂法规又懂薪酬又懂面试排期）

## 第六步：缺口盘点（提交前必做，避免被问穿）

准备任何面向平台的征集/上架材料前，**先做一次双向缺口扫描** —— 两个方向交叉：

| 方向 | 切法 | 得出 |
|---|---|---|
| **平台问什么 × 我们有什么** | 逐条比对平台征集问题 | **答不出的缺口**（材料缺失） |
| **场景要什么 × 资产有什么** | 按「资产就绪」≤3 筛 | **做不了的缺口**（数据缺失） |
| **平台约束 × 机制建没建** | 逐条比对硬约束 | **撑不住的缺口**（工程机制缺失） |

### 三类缺口的典型清单（2026-09 实测，可作模板）

**一类 · 答不出（腾讯 6 问，8 项）**
客户数/注册数 · 活跃用户绝对数 · 底层模型 · Agent 框架 · demo 截图 0 张 · 钉钉飞书未确认 · L2 是否收费 · 试点企业名单为空

**二类 · 做不了（28 场景就绪 ≤3，7 项）**
工签规则库 · 雇主费率库 · 薪酬未结构化 · 发薪/申报日历 · 回访节奏模板 · 管道空表冷启动 · 员工档案空表

**三类 · 撑不住（平台约束，9 项）**
异步任务架构 · 长内容落文档分流 · 7 天续授权机制 · 单连接部署 · 授权引导话术 · 管理员审批材料 · 企微连接器未接 · 推送退订机制 · 运维 owner 未定

### 三条关键判断规则

1. **"竞品都做了" ≠ "我们有数据"。** 5/5 跨市场验证度证明的是**需求真实**，不是**资产就绪**。两者混用会导致立项后做不出来（这是最高频的误判，见 `overseas-hr-benchmark` 第 56 行 vs 第 59 行）。
2. **未确认项（模型/框架/合作平台/收费）不要写进对外材料** —— 宁缺勿编；被追问一次就崩。
3. **数据类缺口不阻塞征集答复。** 平台自己在探索期，要看的是"有真实资产 + 懂平台独特性"。区分清楚：**🔴 补数据类**（不阻塞答复，但决定 Round 排期）vs **🟢 确认类**（问一句就补上，别因为这几项拖着不发）。

### 缺口盘点输出结构

① 结论先行（三类缺口数量 + 最扎心的三条 + 一个隐性缺口）
② 一类缺口逐条表（平台问题 / 要什么 / 我们有 / 不具备 / 补法）
③ 二类缺口按就绪度排序 + 区分「我方缺数据」与「客户侧空表」
④ 三类缺口机制清单
⑤ 按"能否本轮解决"分三堆（今天能补 / 本周能补 / 必须排队）
⑥ 如果只做三件事 + 红线

## 第七步：Agent 交付四件套（从评估到可交付）

规划完成后，一个企微 Agent 的标准交付物是**四件**，缺一件都不算完成：

| # | 交付物 | 内容 | 样例 |
|---|---|---|---|
| 1 | **人设真相源** | 身份卡 / 职责范围（3 项）/ 说话方式 / 交付物模板 / **可直接粘贴的系统提示词** / 数据引用规范 / 不做清单 | `huizhao-bot/huizhao.persona.md` |
| 2 | **可测试原型** | 零依赖本地服务 + 企微风格聊天台，接模型前先验证"长什么样、怎么说话、交付什么" | `huizhao-bot/app.py` + `web/index.html` |
| 3 | **上架介绍文档** | 一页速览 / 简介（是什么+不是什么+与通用 AI 区别）/ 人设 / 核心场景 / 功能清单 / 商业逻辑 / 案例 / 安装授权引导 / 新手引导 / 场景剧本 / 用户旅程 / 平台下一步 / FAQ 索引 / 物料规范 | `2026-09-10_慧招Zoe_企微介绍.md`（+ 同版 HTML） |
| 4 | **命名决策说明** | 名字 = 承诺不是愿景；名实相符 > 服务暗示 | `2026-09-10_命名建议_*.md` |

### 原型的三个关键设计

1. **本地版刻意不调大模型** —— 规则路由 + 静态知识库。目的：无网络、无企微授权也能把**形态与话术**验证清楚。诚实标注"本地演示版"，别让人误以为这是能力上限。
2. **知识库只放零编造风险的内容** —— 自有框架资产（维度清单、阶段索引、扫描词表、渠道框架）+ **从内容库实取并带 `reference_url` 的真实条目**。演示时被追问"数据哪来的"要答得上。
3. **必须做一个"查不到"的例子** —— 问一个未收录国家，Agent 如实回「未收录，需补采」。**这是可信度设计，不是缺陷**，演示时专门展示这一步。

### 命名规则（可直接复用）

- **名字要名实相符**：能力清单里没有的动作，不要写进头衔。称"猎头"却无寻访能力 → 客户第一句就问倒 → 首轮信任损耗
- **平台观感**：「顾问 / 同事」类中性专业词 > 「猎头 / 销售」类商业模式词（企微欢迎"帮 HR 干活"、不欢迎"卖服务"）
- **授权顾虑**：名字会抬高客户对授权面的预期 → 影响冷启动
- **「助理」vs「顾问」**：助理只能"我帮你写"，顾问能说"**我建议**"。人设若偏专业判断，名字要配顾问
- **一个身份原则**：不要同时用两个对外名（阿里 Qoder / QoderWork / 千问办公的教训 —— 内部员工都要分辨）
- **中英双名怎么配**（⚠️ 本规则 2026-09-10 被实战修正过一次，注意看）：有两条合法路径，决策依据是**使用频次**而非"哪个更讲得通"——
  - **语义直连字族**：`Sophie ← sophia＝智慧 → 「慧」`。链路漂亮、能写进品牌手册，但**每次都要解释一句**
  - **谐音直连业务字**：`Zoe ← zhāo＝「招」`。不用解释，**且更短**（4 字母 vs 6 字母）
  - **实战结论（慧招案例）**：B2B 里一个名字要被念/敲几十遍 → **简单 > 语义**，最终定 **Zoe**。
  - **选 Zoe 的两处已知代价（必须配套补）**：① 英文侧与「慧」字族**断链** → 字族锚点由中文名单独承担；② Zoe 在英语世界**偏年轻** → 资历感由职衔「**高级顾问 / Senior Advisor**」承担，不靠改名
  - ❌ 旧版规则「英文名优先接字族语义、别只图谐音」已被推翻 —— 那是"讲得通"优先，忽略了"用起来顺"
- **命名沿革要留档**：Scout → Vivian → 慧招(Sophie) → 慧招(Zoe) 四站都在 `2026-09-10_命名定稿_慧招Zoe.md`。**每换一次都有人要重新认一遍** —— 定下来比选对更重要
- **改名要工具化**：`outputs/name_guard.py` —— `check` 扫旧名残留、`set` 一键换名（默认预演，`--apply` 才写入）。守卫的 `LEGACY` 要随名字迁移累积（Sophie 现在也是旧名）
- **品牌字族**：同母品牌的多个 Agent 共享一个字（慧**思** → 慧**招**），形成字族、降低认知成本

## 第七步：把设计系统落到 Agent 身上（三载体同源）

「把介绍文档那套设计应用到 Agent 上」，有三种落法，**做完是三样东西**，别混为一谈：

| 载体 | 做什么 | 客户感知 |
|---|---|---|
| **① 交付物模板** | Agent 每次产出（JD / 自测报告 / 合同清单 / 法规速查 / 发布方案 / 日历方案）都生成**带封面 + 水印 + 二维码名片 + 统一落款**的品牌文档，而不是聊天框里一段纯文字 | 「她给我的东西能直接转发」 |
| **② 对话界面** | 聊天界面穿品牌设计：品牌蓝渐变头部 + 白卡 logo + 职衔 + 水印层 + 品牌名片（logo / 二维码 / 官网 / 邮箱） | 「她是这家公司的人」 |
| **③ 上架素材** | 应用图标 / 封面横幅 / 能力全景 / 卖点卡 | 「这产品是认真做的」 |

**为什么①最重要**：企微单条回复上限 2048 字节，长内容本来就塞不进聊天框 —— 逼着结论落成文档。既然必须落成文档，就让它落成**有品牌版式的文档**。资产会积累，替换成本随之升高。

### 实施要点（可复用）

1. **设计令牌单点定义**：颜色 / 字体 / 圆角写成一个 dict，HTML 模板全部引用它。改一处，介绍文档、交付物、素材三处同步。
2. **交付物必备四件套**：水印（`position:fixed` 网格层，打印时 Chrome 每页自动重复）+ 二维码名片 + 官网 / 邮箱 + 免责声明。
3. **logo 方向性**：白底 logo 只能放浅色面，深色底必须垫**白卡**。
4. **可打印**：`@page A4` + `print-color-adjust:exact`（不加会全篇白底），打印态容器宽度收窄到 100%。
5. **出图**：素材用「HTML → 无头 Chrome `--screenshot` + `--window-size=出图尺寸`」精确出 PNG，不用设计工具。详见技能 `html-to-pdf-print` 第四节。
6. **⚠️ CSS 类名查重**：短类名（`.dot` / `.tag` / `.list`）被不同组件复用时会发生尺寸继承错误。踩过一次：头部绿点 `.dot{width:6px}` 撞上列表类 `ul.dot`，中文列表塌成单字竖排。**新页面复用短类名前先全局搜同名定义。**
7. **⚠️ 前端不要硬编码后端已有的文案**：页面里的欢迎语若在前端写一份、后端 `greet` 分支又有一份，两份必然漂移（踩过：前端标签「慧招能力总览.pdf」vs 后端文档「海外招聘顾问能力总览」，且交付物改名后前端不动）。做法：**页面加载时 `fetch('/api/chat', {message:'你好'})` 用服务端响应渲染欢迎语**，只在 `catch` 里留一段极简兜底。凡「同一段话出现在两个文件」就是漂移隐患。
8. **⚠️ 交付物标签必须名实相符**：标签文字要能对上它打开的那份文档标题 —— 写「出海招聘合规速览」点开却是「企微交付物落地方案」＝ 客户当场失去信任。改交付物名时，`DOC_META`、handler 的 `deliverables[].name`、打开后的文档标题**三处一起对齐**。
9. **⚠️ 每轮留一个资产要对所有分支成立**：越界/兜底分支（`fallback`）最容易漏 `deliverables`，表现是「除了正题，其它回复都是空手」。兜底恰恰最该递一份**能力总览**。写法：所有 handler 的 `deliverables` 都允许为空时回退到能力总览文档，别让它成为「只管答话、不留东西」的死角。
10. **⚠️ 穷举所有 handler 做冒烟测试**：意图路由分支多起来后，某个分支少写一个局部变量就是 500（踩过：`r_reminder` 漏了 `c = country or "目标国"`，上线后该意图整条不可用）。**写一个脚本遍历全部 handler × （有国家 / 无国家）两种入参**，只跑一遍就能把这类 `NameError` 全扫出来 —— 比逐条手测可靠。
11. **⚠️ 实体识别别用「短别名 + 子串匹配」**：国家/公司这类实体表最容易埋雷。踩过两次，都在同一个 `detect_country()` 里：
    - **假阳性**：别名字典放了 ISO2 码 `de` / `id` / `us` / `in` / `my` / `it` —— `deadline` 命中 `de` → 德国、`candidate 的 ID` 命中 `id` → 印度尼西亚、`tell us` 命中 `us` → 美国。**国别一错，整段回答的框架全错**，比答错一个字严重得多。
    - **假阴性**：20 个国家的表漏了俄罗斯、土耳其、南非、印度、哥伦比亚 —— 用户问俄罗斯，识别成 None，回复直接降级成兜底话术。
    - **多实体歧义**：`印度和越南哪个成本低` 返回了越南 —— 因为按**字典顺序**返回第一个命中，而不是按**在句子里出现的先后**。
    - 正确规则（三条一起上）：① 中文名 / 英文全名 → 子串匹配；② 两字母码 → 必须**独立成词**（`(?<![a-z0-9])xx(?![a-z0-9])`）；③ 与英文常用词同形的码（us/it/my/de/es）→ 还要求**原文大写**，`id`/`in` 干脆不参与；④ 命中多个时按**首次出现位置**取，不按字典顺序。
    - **验收**：写一组「应当识别为 None」的负例（`deadline` / `candidate 的 ID` / `de facto` / `tell us`）和一组正例，一起跑。**只测正例永远发现不了假阳性。**
12. **⚠️ 覆盖状态要如实标记，别让「未收录」伪装成「有内容」**：给每个实体登记 `full / part / gap` 覆盖状态与说明（法规几条、指南有没有）。**gap 时回答必须显式声明「本国内容未收录，下面是评估框架」** —— 演示时被追问数据来源，这一条比任何功能都加分。反面做法是让 Agent 用通用框架硬答，客户事后核对发现条款不存在，信任一次性归零。
    - 选截图做对外材料时，**优先挑有覆盖的实体**（演示观感强），但**别删掉 gap 那条** —— 它恰恰是可信度证据，可作加分项一起给。
13. **⚠️ 前端截图/出图模式要单独留一个开关**：`?bare=1` 之类，让页面在出图时隐藏欢迎语、推荐语、输入框，并能按内容自然撑高。细节见技能 `html-to-pdf-print` 第 4.1 节「两遍法」。

### 一句提醒（本轮踩过的坑）

Agent 的「会干活」最容易在**响应正确但渲染错乱**上翻车。任何界面改动做完，**必须实际截图看一眼**，不能只看接口返回的 JSON 正确。判断标准不是「接口通了」，是「截图上人看得懂」。

### 交付物文档的三个必查项（不然客户一看就露馅）

1. **水印要真的看得见**：水印层 `z-index` 必须高于正文容器，否则被白底盖住 —— 表现是「PDF 里搜得到水印文字，但眼睛看不见」。用「带水印 / 不带水印两版像素差」判定，别用 `get_text`。
2. **中文字体要真嵌入**：macOS 的 PingFang / Hiragino 不允许子集嵌入，Chrome 会转成每页上百个 Type3 字体对象。**打印态单独指定 `Heiti SC`**（可正常嵌入）。判据：`FontFile > 0` 且残留 Type3 = 0。
3. **`--print-to-pdf` 的输入与输出路径都不能含中文**，否则静默失败。统一 `/tmp` 英文名导出后 `cp` 回目的地。

具体命令与判读标准见技能 `html-to-pdf-print` 第四节、第五节。

## 第八步：知识型意图的答法 —— 命中给全、未命中开单（2026-09-11 沉淀）

适用于「查法规 / 查政策 / 查模板」这类**回答必须可溯源、且知识库不可能全覆盖**的意图。以「法规速查」为样板，其余知识型意图照搬。

### 8.1 命中：一条法规给齐八项，且返回 1..N 条不做取舍

一条法规**必须**给齐这八项，缺一项就算不合格：

| # | 字段 | 要求 |
|---|---|---|
| 1 | 原文链接 | 官方发布页（政府公报 / 主管机关站） |
| 2 | 一个慧思链接 | 站内对应条目，便于客户自助细读 |
| 3 | 一个信息源网站 | 第三方权威解析（四大 / 律所 / 官方英文版） |
| 4 | 摘要 | 只写条款要点，不写评价 |
| 5 | 近一年变动 | **带日期**逐条列，草案与已生效**分开标** |
| 6 | 案例 | 判决 / 判例趋势，每条带可点出处 |
| 7 | 参考意见 | 我方判断，与「事实」分开写 |
| 8 | 执行引导 | **分两份**：客户端动作清单 + 内部落地步骤 |

**返回条数**：命中几条就给几条，**不做「挑一条最相关的」这种摘要取舍**。命中多条时先给一张明细表（编号 / 名称 / 状态 / 生效日），再逐条展开。

**为什么八项**：客户拿这条回复是为了**做决定**。只给「法律名称 + 链接」等于让他自己再搜一遍；给了变化与案例，他才能判断「我要不要动合同」；给了执行引导，他才知道「这周先做什么」。少任何一项，这条回复就退化成搜索框。

### 8.2 三链溯源 + 链接校验四态（不假装全通）

**三链**：原文 / 慧思 / 信息源，三个角色固定，各自独立标注状态。目的不是「多给几个链接」，是**让客户能自己复核**。

链接必须**实测**，然后按四态如实标注 —— **绝不把打不开的链接当可用链接给客户**，也**不要因为打不开就删掉**（官方站点的价值恰恰在于是权威源）：

| 状态 | 含义 | 展示 | 触发场景 |
|---|---|---|---|
| `ok` | 已实测 HTTP 200 **且正文真实** | 「已实测」绿标 | 我方 curl 通过，且**不是 WAF 拦截页** |
| `walled` | 官方站点，有反爬 / 地域限制 | 「官方站点」黄标 + 说明 | curl 403/000，**浏览器能正常打开** |
| `gap` | 内容库尚未收录该主题 | 「待补采」灰标 | 站内无对应条目，链接指向板块首页 |
| `unreachable` | 官方源 · **本环境不可达** | 「官方源不可达」红标 | curl 000 **且无头浏览器也超时**（`ERR_TIMED_OUT`）—— 连「浏览器可开」都验证不了 |

**关键认知**：政府站点 curl 打不开是常态（实测 `labour.go.th` 000、`ratchakitcha.soc.go.th` 403、`natlex.ilo.org` 403）。`walled` 标注的是**「能不能 curl 到」，不是「能不能打开」**，所以文案要写「浏览器可正常打开」，否则客户以为链接坏了。

**第四态 `unreachable` 是为什么加的**：`walled` 的文案里承诺了「浏览器可正常打开」。墨西哥的 `dof.gob.mx` / `diputados.gob.mx` 连无头浏览器都超时（`ERR_TIMED_OUT`），**我们再怎么测都无法兑现那句承诺** —— 此时继续标 `walled` 等于替客户打包票。链接照给（它确实是权威官方源），但状态如实写「本环境不可达（curl 000 + 浏览器超时），属地域 / 网络限制，请在使用地复核」。**四态 vs 三态的成本只多一行数据 + 一个徽标 + 一条 CSS，但不加就等于对客户说了假话。**

**顺带一条**：标 `ok` 之前，**返回码只是初筛** —— 200 也可能是 WAF 拦截页（假 200，例：`imss.gob.mx` 返回 200 但正文是 Incapsula 拦截页；`curl -I` 的 HEAD 请求还会被缓存掩盖）。规程是「返回码初筛 → GET 看正文 → 无头浏览器复核」，三步都过才敢标 `ok`。详见 8.7 第 13 条与 8.8。

### 8.3 未命中：不允许只回一句「暂未收录」

这是最容易做错的地方。**知识库没有 ≠ 这条请求结束**。正确做法是把它变成一个**有编号、有时限、有回音**的工单闭环：

```
客户提问 → 未命中
   ↓ 立即开单（编号 HZ-T<当日日期>-<三位序号>，如 HZ-T20260911-001）
   ↓ 前端如实回复：本主题尚未收录，已登记检索工单（含编号 + SLA），有结果即刻反馈
   ↓ 后台按 6 层来源优先级检索（政府 > 四大/律所 > 协会 > 权威媒体 > 企业公告）
   ↓ 回填答案（POST /api/tickets/resolve）→ 状态转「已答复」
   ↓ 主动推送客户 + 补采进条目库
   ↓ 下次同类提问 → 自动带出「此前已有答复」+ 正文（客户不用问第二遍）
```

**五条硬要求**：
1. **编号可引用**：客户能凭编号追问，运营能凭编号定位。格式 `HZ-T{YYYYMMDD}-{当日三位序号}`。
2. **SLA 要写出来**：如「2 个工作日」，别只写「尽快」。
3. **台账 append-only**：一行一单（`.jsonl`），写入用「先写 `.tmp` 再 `os.replace`」保证原子性；读取时**坏行跳过**，别让一条脏数据拖垮整个台账。
4. **⚠️ 开单前必须先查重 —— 同一个问题绝不重复开单**（本轮实测踩到的真缺陷）。三条分支：

   | 情况 | 判断依据 | 行为 | 开新单 |
   |---|---|---|---|
   | 该主题**已答复** | 同实体 + 主题词有交集 + 已有 answer | 直接把历史结论给出去，注明原单号与答复时间 | ❌ |
   | 该主题**在办** | 同实体 + 主题词有交集 + 状态待检索/检索中 | 告知「已在检索中」+ 在办单号，复用原单 | ❌ |
   | **新主题** | 主题词无交集 | 正常开单；若该实体答过其他主题，附一条「我们还答复过：单号（主题）」作参考 | ✅ |

   **为什么**：不查重的后果不是「多一条台账」，而是运营收到一堆重复工单、客户看到单号乱涨却仍是同一份答案，**闭环的可信度直接崩掉**。实测：001 已答复后连问 5 次，台账涨到 6 条，全是同一份答案。
   **两个实现要点**：① 序号取「当日**最大**序号 + 1」，不是「条数 + 1」—— 台账有空洞（作废 / 合并 / 清理）时按条数算会撞上已存在的号；② 主题判断用**词集合求交集**（`劳动法、规定` → `{劳动法, 规定}`），**任一为空或为「未指定主题」一律视为不同主题** —— 宁可开单，也不能把「最低工资」的答案给到「产假」问题上。
5. **回填即闭环**：查重函数（`_ticket_find(region, answered_only=True)`）必须在 `_ticket_new()` **之前**调用 —— 顺序反了就等于每次都重新开单，闭环白做。回填后同类提问自动带出答案 + 交付物（此时交付物是「速查与执行引导」，不是「检索受理单」）。

**为什么重要**：这直接决定了「答不出」时的客户感受。「暂未收录」＝ 这个工具不行；「已受理，编号 XXX，2 个工作日内给结果」＝ 这个团队在认真办。同一件事的两种表述，信任度差一个量级。对外话术务必给**承诺 + 编号**，不给**空承诺**。

### 8.4 执行引导必须分两份，且内部段可剥离

「执行引导」受众不同，**不能合并写**：

- **客户端**：客户这周要做什么（自查项 / 要改的合同条款 / 要留的凭证 / 要通知的人）
- **内部端**：我方要推进什么（补采哪几条 / 谁负责 / 什么时候回访 / 关联哪个产品线话术）

**内部段必须在技术上可剥离**，不能靠「记得别发错版本」。做法：

```python
# 章节标记 internal: True，客户版自动跳过
for i, s in enumerate(spec.get("sections", []), 1):
    if s.get("internal") and spec.get("client"):
        continue
    badge = "<span class='sec-i'>内部</span>" if s.get("internal") else ""
```

- 交付物接口加 `&client=1` → 生成客户版
- 屏幕上内部段带**红色「内部」徽标**（视觉警示，避免运营误把内部版发出去）
- **验收必须核 PDF 文本层**：内部关键词在客户版中出现次数必须为 0。别只看 HTML 源码 —— 要看最终 PDF。

**踩过的坑**：`str.replace` 替换封面结论文案时，静态文案里带「目标国」占位，命中/未命中两个分支若不分别生成，PDF 封面会印着「目标国已收录法规条目」这种半成品。改法：`concl = concl.replace("目标国", c)`，且 `regulation` 分支按命中/未命中**各写一套结论**。复检时小心 `"目标国" in T` 会误命中 meta 表字段名「目标国**家**」—— 用负向断言 `r"目标国(?!家)"`。

### 8.5 企微 2048 字节：完整条目必然超限，要主动裁剪

一条法规八项字段完整展开约 **18–20 KB**（实测 `20335` 字节），企微单条上限 **2048 字节** —— 必然超限，且**不是超一点**，是超十倍。

**解法不是压缩文案，是分开两种形态**：

| 形态 | 内容 | 用途 |
|---|---|---|
| **企微实发版** | 概览 + 三链精简（URL 去协议与 `www.`）+ 文档指向 + 前 3 步 | 聊天框实时回复 |
| **交付物文档** | 八项完整条目 | 客户点开细读 / 转发 |

**实发版写法**：`概览（命中 N 条）→ 三链精简 → 完整内容在《XXX.pdf》→ 你先做这 3 步`。让客户知道「完整版在哪」，而不是觉得「就这些」。

**自校验字段**：接口返回体里附 `wecom` 字段，运行时可查：

```python
WECOM_LIMIT = 2048
def _wecom(data):
    txt = data.get("wecom_text") or data.get("conclusion", "")
    n = len(txt.encode("utf-8"))
    return {"limit": WECOM_LIMIT, "bytes": n, "fits": n <= WECOM_LIMIT, "text": txt}
```

**注意按字节算**：`len(txt.encode("utf-8"))`，中文一字 3 字节，**不要用 `len(txt)` 字符数**。
**验收**：遍历全部意图跑一遍，输出 `字节/2048`，任何一条 `fits:false` 就算不通过。

### 8.5.1 ⚠️ 裁剪函数必须自己守预算，绝不能靠「调文案长度」

**这是最容易在扩容时翻车的地方。** 实测：第一版裁剪器按当时的 1 个国家、2 条条目调到 1809 字节很舒服；**新增一个国家后直接涨到 2265 超限**。

原因很朴素：**只要「裁剪」是人肉按当前数据调出来的，业务数据一增长就会再次失效**。条目数会加、标题会变长、摘要会变长 —— 你不能每次都回去调字数。

正确做法：把裁剪写成**按字节硬兜底**的结构，让函数自己保证不越界：

```python
WECOM_MARGIN = 96          # 预留余量：不同客户端统计口径会有细微差异

def _fit(head, body, tail, limit=None):
    """「必留头部 + 可截断主体 + 必留尾部」拼成不超过 limit 字节的文本。

    head / tail 永远保留 —— 保证客户至少看到「命中了什么」和「完整内容在哪」；
    body 放不下就丢尾部行并补一句「篇幅所限，完整条目见交付物文档」；
    仍超就按字节截断（_cut_bytes 不会切坏多字节字符）。
    """
    limit = limit or (WECOM_LIMIT - WECOM_MARGIN)
    def size(xs): return len("\n".join(xs).encode("utf-8"))
    if size(head + body + tail) <= limit:
        return "\n".join(head + body + tail)
    cut = list(body)
    while cut and size(head + cut + ["", "（篇幅所限，完整条目见上方交付物文档）"] + tail) > limit:
        cut.pop()
    out = "\n".join(head + cut + ["", "（篇幅所限，完整条目见上方交付物文档）"] + tail)
    return _cut_bytes(out, limit)
```

**配套两个小工具**（都是本轮踩出来的观感问题）：
- `_cut_sent(s, n)`：截断中文长句时**优先在 。；，、 处收尾**。直接用 `s[:n]` 会断出「按周排班时单日…」这种半句。
- `_eff_short(e)`：数据里的「时效」字段可能是长句（如「母法 2021-01-01；修订条款分两批生效：…」），在实发版里白占上百字节且客户不关心。压成「分批生效，最近 2026-07-01」一行即可。

**所有裁剪器都要走 `_fit`**（命中版 / 未命中版 / 历史答复版），不要只给其中一个加保护。

**不要用 `_wecom()` 里的静默截断来兜底** —— 那会让 `fits` 永远是 `true`，覆盖掉回归测试的告警能力。`_fit()` 负责产出合规文本，`_wecom()` 负责**如实报告**字节与 fits，两者分工不能混。

### 8.6 事实数据要抽到独立模块，别混在路由逻辑里

法规条目会持续增长（今年 2 条，明年可能 200 条）。几百行事实性数据混在 `app.py` 的路由逻辑里，结果是**改一条要翻半天，而且没人敢动**。

做法：`regdata.py` 独立模块，只放数据 + 查询函数 + 自检：

```python
VERSION = "1.0"; UPDATED = "2026-09-11"
LINK_ROLES = ["原文", "慧思", "信息源"]
REG_DB = {"泰国": [ {...}, {...} ]}
def countries(): return sorted(REG_DB.keys())
def entries(country): return REG_DB.get(country, [])
def topic_hint(country, text=""): ...   # 粗提主题，只归类不猜条款
def selfcheck(): ...                    # 条目完整性 + 链接角色 + 待核实项自检
```

`app.py` 只 `import regdata`。**好处**：数据可独立自检（`python3 regdata.py` 直接出完整性报告）、可由非工程同学维护、可版本化。

**踩过的坑**：`topic_hint` 的关键词表初版只有 25 项，问「南非劳动法有什么规定」时主题被记为「未指定主题」—— 因为词表里没有「劳动法」这个词，只有「劳动合同」。**扩到 40 项**（补劳动法 / 劳动保护 / 法规 / 法律 / 条例 / 规定 / 政策 / 法定 / 薪酬 / 病假 / 遣散 / 试用期 / 公积金 / 外籍 / 平等 / 居家）。教训：关键词表要覆盖**用户口语说法**，不是条款学名。

### 8.7 ⚠️ 每新增一个国家，都要跑一遍「扩容回归十三件事」（2026-09-11 印尼 + 沙特 + 阿联酋 + 墨西哥四轮沉淀）

条目库扩容时反复暴露同一类问题：**数据加进去了，但用户问不进来 / 问进来了答非所问**。十三件事缺一件，扩容就是白做。

| # | 要回归的事 | 实测结果 |
|---|---|---|
| 1 | **意图词典**：拿最口语化的问法试 | ❌ 印尼轮：「印尼**调薪**要按哪个省的档位」「印尼**外包**能裁掉多少人」**都掉进 fallback**。❌ 沙特轮：`沙特化 / 本地化 / 配额 / 认证 / Nitaqat` 也全不在词典里。❌ 阿联酋轮：`阿联酋化` 不在，且**两类更隐蔽的说法也全掉兜底**（见第 11 条）。❌ 墨西哥轮：`加班 / 考勤 / 稽查 / 椅子法 / 分包 / 工伤` 不在，且**「48 小时改 40 小时」这种口语化说法也掉兜底**（见第 13 条） |
| 2 | **主题词典**（`topic_hint`） | ❌ 「缅甸的**外包**规定」工单主题只记成「**规定**」，有区分度的信息被丢掉 → 查重与归档退化成「一锅端」。沙特轮再补 `沙特化 / 本地化 / 配额 / 工签 / 离职补偿 / 合同认证`；墨西哥轮补 `椅子法 / 劳动稽查 / 稽查 / 考勤 / 电子考勤 / UMA / 举报` |
| 3 | **企微字节**：一条一条量 | ✅ 泰国 1372 / 越南 1438 / 印尼 1834 / 沙特 1446 / 阿联酋 1372 / **墨西哥 1812**（六条口径）< 2048 —— 靠的是 `_fit()` 按字节硬兜底，不是靠调文案。**注意别被巧合骗到**：泰国与阿联酋同为 1372（都是 2 条、结构同构），要 dump 出 `wecom.text` 确认内容没串味 |
| 4 | **覆盖度提示**：是否说过期话术 | ✅ 已改为实时读 `regdata.entries()`，不会再说「未收录」 |
| 5 | **交付物名实是否相符**（对了两处） | ❌ 标题写「老挝 法规检索受理单」、元信息表「交付物类型」却写「法规速查与执行引导」—— **一份文件两个身份**。修法：`build_doc()` 返回前回填 `meta[2] = ["交付物类型", name]`。❌ 阿联酋轮又抓到第二种：**国别无关的意图被挂上了识别失败的前缀** —— `reminder`（「给我一份合规到期提醒的方案」）的交付物名叫 `未识别_合规日历方案.md`，读起来像识别失败。修法：没识别到国家时不加国家前缀；元信息表「目标国家」写「不适用（本方案与国别无关）」。**「名实相符」要问的是「这个名字描述的是这份文件吗」，而不只是「标题和类型对不对得上」** |
| 6 | **国家词典 + 未识别兜底值** | ❌ 国家词典只有 ~30 国，问「老挝劳动法」时国家为 `None`，**工单台账的国家字段被写成模板占位符「目标国」** —— 运营按国家筛选看到假国家名。修法：词典扩到 60+ 国；新增 `UNKNOWN_COUNTRY = "未识别"` 替掉所有 `country or "目标国"` |
| 7 | **国别误判防护**（三层，第三层是阿联酋轮新增） | ①**别给英文常用词形的码**：扩国家时**一律不给两字母 ISO 码** —— `be / ma / la / pa / om / se / ch / il / eg` 是英文常用词或缩写（"should be noted" 的 be、"e.g." 的 eg），按「独立成词」规则会被判成国别。②**码没错但撞已收录国家的俗称**：沙特的 `sa` 同时是南非的口语缩写（南非 ISO 是 za，但文档里普遍写 SA）—— 撞的是**业务**不是词汇，更难自查。③**码没错但撞常见职业缩写**（阿联酋轮）：阿联酋曾想加 `ae`，实测 `the ae team is on it`、`share the file ae` **都被判成阿联酋** —— AE 在英文里常指 Account Executive。修法：三处都删（裸 `sa` / 裸 `ae`），对应问句返回**未识别**（宁可不猜，不猜错）。**判断一个码能不能加，要过三道：是不是英文单词 → 在已收录国家里有没有别的俗称 → 是不是常见职业/业务缩写。** |
| 8 | **意图路由顺序**（沙特轮新增） | ❌ 「沙特 **Qiwa 合同认证**要怎么办」被判成 `contract`（含「合同」，而 `contract` 原本排在 `regulation` 之前）—— 用户问合规义务与办理流程，拿到的却是合同模板清单。**两个意图都会命中时，顺序决定了答案对不对。** 修法：把 `regulation` 提到 `contract` 之前，并补 `认证` 词；调整后 20 条用例回归确认无回退 |
| 9 | **客户版导语是否提到被剥离的段**（沙特轮新增） | ❌ 客户版封面导语写「并分列客户端与**内部执行引导**」，而 `&client=1` 会把该段剥掉 —— 客户会去找一个不存在的章节。**「一份文件一个身份」不只指标题与类型，也指版本措辞。** 修法：`build_doc()` 加 `client` 参数，客户版换成中性措辞；导出 PDF 后实测客户版泄漏为 0 |
| 10 | **同一个词跨意图时，归属必须显式定义**（阿联酋轮新增，**最容易漏的一类**） | ❌ `RULES` 是**线性先到先得**，所以一个词放哪边都会错一边：「阿布扎比**试用期**多久」只在 `reminder` 词典里时有 → 被判成**提醒**；把「试用期」补进 `regulation` 之后，**反过来把「试用期到期提醒」拉成了法规**。修法：在进 `RULES` 之前加一层**组合消解** `INTENT_OVERRIDES = [([["试用期"], ["提醒","到期","转正","续签"]], "reminder")]`，即「两个词组同时命中才归某意图」。⚠️ **不能图省事把 `reminder` 整体提前** —— 它含「签证」这类宽词，会让「阿联酋签证有什么新规」也一起跑偏（这条是真跑过的反例） |
| 11 | **「用法名直接问」和「问新规」是两种最容易漏的说法**（阿联酋轮新增） | ❌ 「泰国**劳动保护法**有什么新变化」掉进兜底 —— 因为「劳动保护法」里**不含**「劳动法」这三个字，而它正是这个产品的旗舰案例名；❌「阿联酋签证有什么**新规**」不命中任何法规词，被 `reminder` 的「签证」抢走。修法：`regulation` 再补 `新规 / 新政 / 劳动保护法 / 劳工法 / 劳动法典 / 劳动合同法 / 雇佣法 / 劳资`。**启示：法规词的写法远多于「法规／法律／规定」三种，法名、口语简称、「新规／新政／修订」都要覆盖。** |
| 12 | **兜底文案的作用域过宽 —— 把正常交付件说成废件**（阿联酋轮新增，**最伤客户观感的一类**） | ❌ 封面结论的「未识别到具体目标国家，因此**不作为正式交付**」原本对**所有意图**生效 —— 于是 `greet` / `doc` / `fallback` 这三份**本来就与国别无关**的能力总览与落地方案，封面也被写成废件（实测三份全中）；`reminder` 还因此和元信息表的「不适用（本方案与国别无关）」**自相矛盾**（同一份文件自己打自己）。修法：新增 `COUNTRY_AGNOSTIC_INTENTS = {reminder, doc, greet, fallback}`，国别未识别时这些意图**保留自身结论文案**；`regulation / jd / selfcheck / contract` 仍照常告警。**启示：每写一个「兜底/降级」分支，都要问一句「这个分支的作用域是什么？」—— 兜底最容易顺手写成全局。** 回归时要**正反两组都跑**：不适用兜底的意图不该误报，适用的意图不能丢失告警。 |
| 13 | **官方链自检只看返回码 —— 200 也可能是 WAF 拦截页（假 200）**（墨西哥轮新增，**最容易把假链当权威源给客户的一类**） | ❌ 墨西哥 `imss.gob.mx`（含其托管的 `LFT.pdf`）返回 **200**，一度以为找到了「政府官网托管的劳动法全文」—— 实际 `Content-Type: text/html` + `Content-Length: 847` + `X-Iinfo` 响应头，正文是 `Request unsuccessful. Incapsula incident ID ...`（WAF 拦截页）。**更隐蔽的是 `curl -I`（HEAD）会拿到缓存的 200，只有 GET 看正文才暴露。** 同一轮还遇到「本环境完全不可达」的官方源（`dof.gob.mx` / `diputados.gob.mx`：curl 000 **且无头浏览器 `ERR_TIMED_OUT`**）。修法：① 新增第四链接态 `unreachable`，把「本环境完全不可达」与「有防护但浏览器可开」在**数据层与渲染层**都分开；② 自检规程改为「**返回码初筛 → GET 看正文 → 无头浏览器复核真实渲染**」，两者都过才敢标 `已实测`；③ 假 200 站点不采用。**启示：链接校验的判据是「人打得开吗」，不是「返回码是几」。** |

> **第 7 条的修法参考**（扩词典前先想清楚「哪些码不能加」）：只有**不是英文单词、也不是常见职业/业务缩写、且不与已收录国家俗称撞车**的两字母码才可直接启用；其余一律进 `_ISO_UPPER_ONLY`（要求原文大写）或干脆不给。**代价不对称**：漏一个码最多是识别不到，多加一个码会让整句英文被误判国籍。

**第 1 条的修法**（`RULES` 里 `regulation` 分支补词，四轮累计）：
```
印尼轮：薪资 / 调薪 / 涨薪 / 加薪 / 用工成本 / 外包 / 派遣 / 劳务 / 遣散 / 裁员 / 赔偿 / 产假 / 陪产 / 年假 / 病假 / 竞业
沙特轮：沙特化 / 本地化 / 配额 / 工签 / 补偿 / Nitaqat / 认证
阿联酋轮：阿联酋化 / 试用期 / 新规 / 新政 / 劳动保护法 / 劳工法 / 劳动法典 / 劳动合同法 / 雇佣法 / 劳资
墨西哥轮：加班 / 考勤 / 稽查 / 椅子法 / 分包 / 工伤 / 工作周 / 周工时 / 工时上限 / 每周工作 / 40 小时 / 48 小时
```
> **核心教训**：意图词典、主题词典、国家词典都是按「当时已有的国家」写出来的。**新国家会带进一批新说法、新国家名，还会撞出路由顺序、跨意图冲突、兜底作用域、版本措辞、命名适用性与官方链可信度的问题** —— 沙特轮与阿联酋轮的坑（第 8–12 条）**没有一个是「词典缺词」，全是「词都在，但归属、顺序、作用域、文案、命名没跟上」**；墨西哥轮则各占一半（第 1 条是缺词 —— 而且缺的是「48 小时 / 40 小时」这种**口语化的数字说法**；第 13 条是**自检方法**本身的漏洞）。所以**扩容的验收标准不是「条目库自检通过」，而是「① 用口语化问法能命中（含法名直问、含用「几小时」这种口语谈工时）② 答的内容对得上问题 ③ 一份文件只有一个身份（标题/类型/版本措辞/国别适用性四处都不能打架）④ 客户版不提到被剥离的段 ⑤ 两字母码不制造歧义 ⑥ 跨意图的词有显式归属 ⑦ 兜底文案有明确作用域（正反两组都跑）⑧ 官方链自检不只看返回码（含 GET 看正文 + 浏览器复核）」**。

### 8.8 找官方原文的路径探测法（政府站点多数不可直连，别按一个模式假设）

**结论：政府站点的 PDF 路径有固定模式，但可用性差异极大，必须逐个实测。** 印尼这一轮实测出的规律：

| 站点 | 结果 |
|---|---|
| `jdih.kemnaker.go.id/asset/data_puu/<年份><类型><编号>.pdf` | ✅ **可直连**（`2025pp049.pdf` / `2003uu013.pdf` / `2023uu006.pdf` 均 200） |
| `peraturan.go.id/files/...` | ❌ 000（连不上） |
| `peraturan.bpk.go.id/Details/...` | ❌ 403（反爬） |
| `bphn.jdihn.go.id/common/dokumen/...` | ❌ 000 |
| `bpjsketenagakerjaan.go.id/assets/uploads/peraturan/...` | ✅ 可直连（JKP 的 PP 6/2025 从这儿拿到） |

**做法**：
1. 先按站点命名规律**猜 3–4 个候选路径**，用 `curl -o /dev/null -w "%{http_code}" -A "<浏览器 UA>" -L` 批量验（带 UA 很关键，不少站点按 UA 拦）
2. 拿不到官方原件时，**不要硬凑**：用「官方签署文本的镜像全文」并在 label 里写明「镜像站，原始出处 <官方域名>」，同时把该官方门户首页放进 `extra`
3. `state` **四态**如实标注：`ok`（实测 200 **且正文真实**）/ `walled`（403 或 000，**浏览器可开**）/ `gap`（内容库未收录）/ `unreachable`（**本环境连浏览器都打不开**，不承诺浏览器可开）
4. 一个 PDF 一个 `curl`，**别一次几十个**：慢站点会把整批拖住

> 顺带一个反直觉的发现：**搜到的转载站（律所、通讯社、NGO）往往比政府站更可用**。AHP / BDO / ANTARA / ASEAN Briefing 这类站点全部 200，而 `peraturan.go.id`、`business-humanrights.org`、`publiceye.ch`、`voi.id` 都是 000。所以**信息源链要用这些可达站，原文链才去啃官方**，两条链互为兜底。

**沙特这一轮又补了两条规律**（2026-09-11）：

| 站点 | 结果 |
|---|---|
| `qiwa.sa`（劳工部官方服务平台，MHRSD 下属） | ✅ **可直连** —— `/en`、`/en/services/labor-law`、`/en/services/contracts` 均 200，可作原文链 |
| `uqn.gov.sa`（官方公报 Umm al-Qura）首页与检索 | ✅ 可直连 200 |
| `www.hrsd.gov.sa/fil/node/<id>`（MHRSD 官方新闻公告短路径） | ✅ 可直连 200，**是最稳的官方引用点** |
| `www.hrsd.gov.sa/`（MHRSD 根路径） | ✅ 可直连 |
| `www.hrsd.gov.sa/en/media-center/...`（长的频道 URL） | ❌ 000（WAF 按路径拦） |
| `laws.boe.gov.sa` / `www.boe.gov.sa`（沙特法规门户） | ❌ 000 |
| `ilo.org/sites/default/files/...`（联合国机构 PDF） | ❌ 403（walled，浏览器可开） |

> **可复用的一条（比 8.8 更细）**：**同一域名的不同路径，可用性可能完全不同** —— `www.hrsd.gov.sa/` 是 200，而 `www.hrsd.gov.sa/en/media-center/news/<超长阿拉伯文 URL>` 是 000。所以探测必须按「域名 **+ 具体路径**」逐条测，不能因为根路径通就假设子路径也通（也不能反过来）。**找官方公告优先用 `/fil/node/<id>` 这类短路径**，含大量百分号编码的长 URL 更容易被 WAF 拦掉。

**阿联酋这一轮补了第三组规律（2026-09-11）**：

| 站点 | 结果 |
|---|---|
| `u.ae`（阿联酋联邦政府官方门户） | ✅ **可直连 200**，可作原文链 —— 但见下方 HTTP/2 陷阱 |
| `mohre.gov.ae`（人力资源与阿联酋化部） | ❌ 403 / 000（walled） |
| `uaelegislation.gov.ae`（联邦法规门户） | ❌ 000（walled） |
| Schlüter Graf / Al Ramsy / GSDA / UAELaw / Caliberly / OVI / TheAccntnt / ZETUP / Kayrouz | ✅ 全部 200（第三方交叉验证链的主力） |

> ⚠️ **新坑：`curl` 返回 000 不等于死链 —— 可能是 HTTP/2 协商失败。** 实测 `u.ae`：默认 `curl` 返回 **000**，加 `--http1.1` 立刻 **200**；用无头浏览器打开 `status=200` 且标题正常（`Jobs | The Official Platform of the UAE Government`）。**所以「导出前自检源 URL」这一步不能只看 curl 的返回码**：拿到 000 时先用 `--http1.1` 复测一次，再用浏览器（或 `wait_until='commit'`）确认一遍，**别把能打开的官方链当死链删掉**（对照：`domcontentloaded` 会因慢资源超时，这次就误报过一次）。
>
> 还有一条口径纠错的经验可复用：阿联酋条目里发现网上**多篇仍在流传旧法**（「辞职时离职补偿按 1/3、2/3 折减」，2021 年联邦法令 33/2021 已取消）。**入库时要拿 4 个以上来源交叉确认「旧规则是否已废」，并把纠正写进 `caveats`**，否则会跟着旧文抄。另外阿联酋化 2026 的月缴罚金有 **AED 8,000 / 9,000 / 10,000 三说** —— 多源冲突时**如实并列 + 标「待官方确认」**，不挑一个顺眼的当事实。

**墨西哥这一轮补了第四组规律 + 两个新坑型（2026-09-11）**：

墨西哥是第一个**官方链以西语为主**的国家（`dof.gob.mx` 官方公报 / `stps.gob.mx` 劳工部 / `diputados.gob.mx` 法条库）。

| 站点 / 路径 | 结果 |
|---|---|
| `www.stps.gob.mx/gobmx/estadisticas/`（劳工部统计页） | ✅ **可直连 200，真实西语页面 —— 唯一可直连的真官方页**，用作稽查条目原文链 |
| `www.stps.gob.mx/`（根路径） | ⚠️ curl 200，但**浏览器里会跳转到 `gob.mx/stps` 并被 Access Denied** → 按 walled 处理 |
| `www.stps.gob.mx/gobmx/` | ❌ 403 |
| `www.gob.mx`（联邦政府门户） | ❌ **全线 403（连无头浏览器也 Access Denied）** → walled |
| `www.dof.gob.mx`（官方公报） | ❌ **000 + 无头浏览器 `ERR_TIMED_OUT`** → 第四态 `unreachable` |
| `www.diputados.gob.mx/LeyesBiblio/pdf/LFT.pdf`（劳动法全文） | ❌ **000 + 无头浏览器超时** → 第四态 `unreachable` |
| `www.imss.gob.mx`（社保局，含托管 PDF） | ⚠️ **200 但是假 200** —— 正文是 Incapsula 拦截页，不采用 |

> ⚠️ **新坑型一：假 200（返回码 200 ≠ 可用）。** `imss.gob.mx` 返回 200，但 `Content-Type: text/html` + `Content-Length: 847` + `X-Iinfo` 头，正文是 `<iframe id="main-iframe" src="/_Incapsula_Resource?...">Request unsuccessful. Incapsula incident ID ...`。**关键细节：`curl -I`（HEAD）拿到的是缓存的 200 + `text/html`，只有 GET 看正文才暴露**（且 HEAD 快、GET 慢约 6 秒）。所以自检要三步：**返回码初筛 → `curl -sL` 看正文有没有拦截页特征（Incapsula / Cloudflare / Access Denied）→ 无头浏览器复核真实渲染**。三步都过才标 `ok`。
>
> ⚠️ **新坑型二：`unreachable` 是与 `walled` 不同的一态 —— 因为 `walled` 的文案里承诺了「浏览器可正常打开」。** `dof.gob.mx` / `diputados.gob.mx` 连无头浏览器都 `ERR_TIMED_OUT`，我们再怎么测都无法兑现那句承诺。**链接照给（它确实是权威官方源），但状态如实说清「本环境不可达，请在使用地复核」** —— 这就是第四态存在的全部理由：**验证不了的事，不替客户打包票。** 三态扩四态的成本极低（数据层 `LINK_STATE` 加一项 + 渲染层 `LINK_STATE_UI` 加一项 + 一条 CSS 类），但不加就等于对客户说了假话。

> **可复用的第三条**：**同一域名的不同路径可用性差异，在墨西哥又出现一次** —— `stps.gob.mx/gobmx/estadisticas/` 通、`/gobmx/` 403、根路径浏览器跳转被拒。**官方链要测到具体路径，不能测到域名就下结论**（与沙特 `/fil/node/<id>` 那条同源）。

### 8.9 PDF 质检的两个正则陷阱（2026-09-11 实测踩到）

导出的 PDF 做完质检后要人工复核告警——**有一条是误报**：

1. **`目标国家(?!家)` 会把元信息表的字段标签当占位符残留**。文档头部有一张「客户名称｜（请填写）／**目标国家**｜印度尼西亚／……」，标签词本身就叫「目标国家」，但值已正确填入。判据要改成**「标签后跟 `（请填写）` 或 `___`」**，而不是只匹配标签词。
2. **剥标签做「内部段泄露」检测前，必须先剥 `<style>`**。CSS 注释里写了 `/* 内部段：… */`，直接 `re.sub(r'<[^>]+>', '', html)` 会把注释内容算进正文，造成「客户版含内部字样」的误报。

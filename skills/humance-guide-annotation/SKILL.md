# 慧思国别指南更新标注 · 落标执行器

**定位**：内容校对工作流的**执行侧**（写操作）。
上游 `humance-content-baseline` 只管盘点（只读，产出差异）；本技能管**差异怎么落到页面上**。

```
校对出差异（B2-xx CSV）
   ↓  本技能
筛选可落标项 → 申报式正文修复（references/body-fixes.json）→ 生成标注块 → 落位到章节锚点 → 一次校验（QC 31 项，含官方外链可达 + 内容质量 + 页面可见性 + 申报修复）→ 预览 → 台账
   ↓  release_stage.py（阶段一：本地暂存 + 二次校验·全文校验 19 项 + 通知「待上线」）
本地暂存（**线上零改动**） → 通知 Yoyo → 人工确认
   ↓  release_apply.py --approve …（阶段二：前置 P 组门禁）
写 Strapi → 按 documentId 回查 sha256
   ↓  verify_secondary.py --source live（阶段 C：三次校验 · 线上回读）
三次校验 → 回写台账（二次/三次校验各记一组，不互相覆盖）
```

## 冷启动三步（新批次照抄）

```bash
S=~/.workbuddy/skills/humance-guide-annotation

# ① 复制批次配置，改两侧：countries（documentId/slug/教材页版本）+ notes（锚点/内容）
cp $S/references/batches/b2-01-t.json  $S/references/batches/b2-0x.json

# ② 本地试跑（默认，绝不碰线上）→ AFTER + 门禁 + 报告
python3 $S/scripts/batch_guide_patch.py --config $S/references/batches/b2-0x.json \
        --workdir <build目录>

# ③ 真渲染验证（防 flex 错位 / 配色漂移）+ 出交付物
python3 $S/scripts/verify_render.py --workdir <build目录> --shot <截图目录>
python3 $S/scripts/build_section_preview.py --config $S/references/batches/b2-0x.json \
        --workdir <build目录> --out <交付目录>/分章视图预览.html
python3 $S/scripts/build_preview.py --config $S/references/batches/b2-0x.json \
        --workdir <build目录> --out <交付目录>/完整预览.html
python3 $S/scripts/make_ledger.py   --workdir <build目录> \
        --proofread-csv <B2-xx diff CSV> --outdir <输出目录> --prefix <前缀>

# ④ 一次校验 · 上线前 QC（可独立跑；--apply 也会自动调它，过不了就拒绝写入）
python3 $S/scripts/qc_gate.py --config $S/references/batches/b2-0x.json \
        --workdir <build目录> --md-out <交付目录>/一次校验_上线前QC报告.md

# ⑤ ★ 两阶段发布（2026-09-23 Yoyo 定：**校验全过 → 存本地 → 通知我确认 → 才上线**）
#    ⑤-1 阶段一：本地构建 + 一次校验(QC 24) + 二次校验(全文校验·暂存稿 14) + 落暂存清单 + 发「待上线确认」通知
python3 $S/scripts/release_stage.py --config $S/references/batches/b2-0x.json \
        --workdir <build目录>                 # 加了 --no-notify 就只暂存不通知
                                              # 通知没发要补发：加 --notify-only
#    ⑤-2 人工确认后（Yoyo 回「上线」）—— 前置跑 P 组门禁，过不了直接拒
python3 $S/scripts/release_gate.py --workdir <build目录> --approve all   # 可只体检
python3 $S/scripts/release_apply.py --workdir <build目录> --approve all

# ⑤-3 应急 / 回滚才允许绕过人工确认（必须加 --legacy）
python3 $S/scripts/batch_guide_patch.py --config ... --workdir ... --apply --legacy
python3 $S/scripts/batch_guide_patch.py --config ... --workdir ... --restore --only <slug>

# ⑥ ★ 阶段 C · 三次校验（上线之后）——回读线上真值跑同一套 S1–S18b；回写飞书台账
#    ⚠️ L9 拦住（外链待人工点验）时：点开链接确认后留痕 → link_check.py --mark-verified <rid,...>
python3 $S/scripts/verify_secondary.py --config $S/references/batches/b2-0x.json \
        --workdir <build目录> --source live --sync-ledger
```

> **三次校验 / 四道闸门，缺一不可**：
>
> | 次序 | 名称 | 脚本 | 证明什么 | 台账字段 |
> |:-:|---|---|---|---|
> | 1 | **一次校验** · 上线前 QC | `qc_gate.py`（31 项） | 「我打算写的没问题」（含**官方外链真能打开** + **全文排版/配图** + **红色没漏到页面** + **申报的正文修复真落地**） | `QC 状态` |
> | 2 | **二次校验** · 全文校验（暂存稿） | `verify_secondary.py --source staging`（S1–S18b） | 「整篇正文渲染出来没问题」 | `二次校验*` 三列 |
> | 3 | **三次校验** · 全文校验（线上回读） | `verify_secondary.py --source live`（S1–S18b） | 「平台真存下来的没问题」 | `三次校验*` 三列 |
>
> 另加**发布确认闸门**（P 组 7 项）= 「我有没有资格现在上线（前两次校验真过 / 通知送达 / 本人确认 / 未过期未偷改）」。
> **门禁全过 ≠ 可以上线** —— 2026-09-23 Yoyo 定：没有人工确认一律不上线。
> 2026-09-23 的 UAE 事故正是只有一次校验、没有整篇渲染复算时漏掉的。

## 门禁总览（项数与分组的**唯一权威**，别处只引用不复述）

| 闸门 | 脚本 | 项数 | 分组 | 何时跑 | 退出码 |
|---|---|:-:|---|---|:-:|
| **① 一次校验 · 上线前 QC** | `qc_gate.py` | **28 + 条件项** | G 落线资格 2 / L 链接 6–9 / T 文本 8（**T1 口径 = 零未申报改动**）/ **BF 申报修复 1–3**（BF3 恒跑）/ R 前端渲染 2 / E 生效状态 3 / **F 客户向文案 6**（含 F5 无红色档 / F6 未上页面留痕） / **CQ 内容质量 1–4** | 构建后、暂存前 | 0=放行 |
| **② 二次校验 · 全文校验（暂存稿）** | `verify_secondary.py --source staging` | **17 + 条件项** | S1–S17 + **S18/S18b**（有申报修复才有） | 阶段一 `release_stage.py` 内 | 0=放行 |
| **③ 发布确认** | `release_gate.py` | **7** | P1–P7 | `release_apply.py` 之前 | 0=允许上线 |
| **④ 三次校验 · 全文校验（线上回读）** | `verify_secondary.py --source live` | **17 + 条件项** | S1–S17 + S18/S18b（同一套） | 上线之后（阶段 C） | 0=可写台账 |

> 阿联酋批次（B2-01-T-migrate）实测：一次校验 **31 项** / 二次校验 **19 项**。

> L 组项数随配置浮动（L6/L7/L8 只在配了 `interpret_url` / `tool_entries` 时才生成）—— 所以写「6–9」而不是固定值。
> CQ 组同理：`CQ1` 配图来源恒跑；`CQ2/CQ3` 只在 `--cq-mode live` 或真出现破图时生成；`CQ4` 只在有豁免命中时生成。
> F 组同理：`F5` 恒跑（查产物有没有红色档）；`F6` 只在真有未上页面条目时才生成。
> BF 组同理：`BF3`（注册表字段自检）恒跑；`BF1/BF2` 只在**该国有申报条目**时才生成。
>
> 门禁必须做**负向测试**才立得住：③ 的负向测试脚本 = `scripts/selftest_release_gate.py`（13 例，含「无清单时全项 fail-closed」「偷改暂存稿」「过期」「无确认凭据」等）；①②④ 的负向测试 = `scripts/selftest_gates.py`（**46 例**，含 F1/F2/F3/F4 客户向文案四项、R1 危险邻接、L5 死链阻断、L9 无点验留痕阻断、**E1–E3 响应体分类器单测**、**N12 官方外链指向被换 / N13 旧状态文案回流 / N14 校对批次回流 / N15–N16 红色档回流（两个入口）**、**N17 申报之外的正文改动仍拦 / N18 申报修复未落地必拦**、**F1–F12c 内容质量 · 配色 · 页面可见性口径纯函数单测**、**G1–G7 申报式正文修复口径单测（含 G1b「申报了却没落地必须判不等」这条防假通过的核心性质）**，以及 D1 夹具放行 / D2 真实验收两级反向验证）。两个脚本跑完退出码都须为 0。
>
> **负向测试分两层**：门禁逻辑用**夹具**测（改 `_link_check.json` 缓存 / 造纯函数夹具，不联网 ⇒ 结论确定）；
> **分类器**用**合成响应体**测（「代理恰好返回 WAF 页」这种输入没法按需复现，只能自己造）。
> 上游判错，门禁只是"精确地执行错误的判定" —— 所以分类器必须单独被测。
>
> ⚠️ 内容质量专测必须走**纯函数夹具**，不能往真实产物上注入：真实产物本就有 CI 阻断项，
> 再注入就分不清拦的是"注入的"还是"本来就有的"，等于永远拦。

## 硬约束（不可协商）

| # | 约束 |
|:-:|------|
| 1 | **默认 local-only**：不加 `--apply` 绝不发 PUT。试跑就是真试跑；配置 `mode` 非 `production-ready` 时拒绝写入 |
| 2 | **ORIGINAL 永不覆盖**：首次落盘后只读；`--refresh` 才重拉且旧档转存 `.prev` |
| 3 | **只 PUT `content` / `previewContent`**，其余字段零改动（`previewContent` 平台会忽略并自行派生，见规范 §11.5） |
| 4 | **数值类只进标注块**，正文表格数字零改动（人工确认后才转正） |
| 5 | **来源存疑不上线**：来源层级=存疑 / 层级 < 权威媒体 → 挡在门外，另立溯源清单 |
| 6 | **「已正式生效 / 计划变更」按生效日判定，并写明** ★（2026-09-23 修订，同日再改为**客户向文案**）：状态判定唯一实现 = `effective_state(effective, asof)`，口径是**法规生效日 vs 标注写入日**（当日生效算已生效）。页面文案必须同时表达两个维度 —— 例「⏳ 待更新 · 已正式生效」（**待更新** = 页面正文还没改，**已正式生效** = 法规本身已落地），**不允许只写裸的「已生效」**（会让人误读成正文已更新）。文案常量唯一真相源 = `guide_patch_lib.EFF_TEXT`（改文案只改那一处）。触发场景：2026-06-01 生效的条目线上显示成「计划」，实际早已生效 |
| 7 | **返回 200 ≠ 成功**：必须按 `documentId` 回查；比 sha 前**先剥 `<style>`**（平台会注入作用域前缀） |
| 8 | **涉地区表述不代为定性**：只标记待人工确认 |
| 9 | **注入位置必须在 `content-section` 内**：前端按章渲染、骨架丢弃顶层元素与 `<style>`（规范 §11） |
| 10 | **线上已有旧格式标注的国家，先跑 `migrate_existing.py` 反抽**，禁止用批次配置直接重建（会回退） |
| 11 | **来源必须回溯到一手源，链接两分法** ★：律所解读 / 行业平台汇编 / 媒体转载**都不算官方源**（规范 §12）。顺序 = ① 读发文出处，判断是否一手 → ② 非一手则继续回溯到政府门户（`u.ae`）/ 主管部门（`mohre.gov.ae`）/ 监管机构（`gpssa.gov.ae`）/ 联邦立法门户（`uaelegislation.gov.ae`）的原文或官方新闻稿 → ③ **标注块链接两分法**：站外**只放「官方原文 ↗」**（`official_url`，必为 official）；站内可放「解读：… ↗」（`interpret_url`，必为 humancehr.com/anchorwe.com 等 internal 域名）与「相关工具」胶囊（`tool_entries`，必为 internal）；**站外三方域名一律禁止**（2026-09-22 Yoyo 修订：解读可留但只跳站内、可植入工具入口）。原引（`url`/`orig_source`）只留档在批次配置与飞书台账，不进页面。判定名单唯一真相源 = `references/official-domains.json` |
| 12 | **落线必须过上线前 QC** ★：`batch_guide_patch.py --apply` 内部强制调用 `qc_gate.py`，未通过（退出码 ≠ 0）整批拒绝写入。流程固定「先构建全部国家 → 跑一次 QC → 通过才逐国 PUT」，不留半写状态 |
| 13 | **注入物必须对前端脆弱 walker 安全** ★★（2026-09-23 建，线上事故换来）：① 注入片段内**不得出现 `</div><`**（标签之间至少留一个非 `<` 字符）；② 标注块**内部一律不用 `<div>`**，改用 `<p>/<span>` —— 结构性免疫，即使平台把空白压掉也不会打乱 div 计数。原因见下方「前端脆弱 walker」小节 |
| 14 | **上线必须有人批** ★★（2026-09-23 Yoyo 定）：正式落线只走两阶段发布 —— 阶段一 `release_stage.py`（本地暂存 + 双校验 + 通知「待上线」），阶段二 `release_apply.py --approve <all\|slugs>`（前置 P 组 7 项门禁）。**门禁全过 ≠ 可以上线**，没有明确的人工确认一律不上线；`batch_guide_patch.py --apply` 直接调用会被拒，须显式 `--legacy`（应急/回滚专用） |
| 15 | **上线的必须是被校验过的那一份** ★：`release_apply.py` 直接 PUT **本地暂存产物**，**不重新构建**（防"再算一遍"引入漂移）；PUT 前再核一次 sha 与暂存清单一致，不一致跳过该条。构建逻辑唯一实现 = `guide_patch_lib.build()` |

## 前端脆弱 walker：本技能最贵的一条约束（2026-09-23 事故换来的）★★

**事故**：阿联酋指南线上 12 章只剩前 4 章能显示，`个税`/`福利`/`解雇与争议处理` 等 8 章全部弹
「无法加载内容。h2Content为空。」——内容本身一条没丢（`content` 完整 12 章），是**前端渲染时找不到章节**。

**根因**：前端 `ContentUpdater` 组件按章切分正文时，用的是**朴素字符串计数**（不是 HTML 解析器），
内层循环用 `indexOf` 数 `<div` / `</div>`，且闭合后推进 `u = d + 7` —— 而 `"</div>"` 只有 **6** 个字符，
**每次越过 1 个字符**。于是当 `</div>` 后面**紧贴**下一个标签（`</div><div` 或 `</div></div>`）时，
那个紧贴的标签被**整条跳过**：少算一次 ⇒ div 深度 `f` 失衡 ⇒ 顶层块提前闭合。
更狠的是它还有 `if (f > 0) break;` —— **一旦错位，后面所有章节一起消失**（不是只坏一章）。

我们注入的标注块当时是多层 `<div>` 拼的，行与行之间正好 `</div><div` 紧贴 —— 触发条件全中。

**两条硬约束**（`WALK_UNSAFE = re.compile(r"</div><")`，`validate()` 与 `qc_gate.py` 都据此阻断）：

1. 注入片段内**不得出现 `</div><`**（`harden()` 会自动补换行兜底）
2. 标注块**内部一律不用 `<div>`**，改用 `<p>/<span>`，整个块对前端只呈现 **1 开 1 闭** 的 div
   —— 这是**结构性免疫**：即使平台把标签之间的空白压掉（实测平台会折叠纯空白行），也不会打乱 div 计数。
   > 只补空白也能过，但依赖「平台保留空白」这个未承诺行为；结构化才是一次到位的解法。

**判据**：`frontend_blocks(content)` 返回的章节数 == 指南应有章节数。它对、线上才对。

**P 组七项**（`release_gate.py`）：

| # | 检查 | 拦什么 |
|:-:|---|---|
| P1 | 暂存清单完整（字段 + 产物文件都在） | 清单缺字段 / 产物被删 |
| P2 | 一次校验 · 上线前 QC 全过 | 内容风险（已由上闸门判定，这里核"记录是否真是全过"） |
| P3 | 二次校验 · 全文校验（`source=staging`）全过 | 整篇渲染风险；校验来源必须是 staging（用 live 的结果冒充暂存预验会被拦） |
| P4 | 待上线通知已送达且**四要素齐** | 没通知到人 = 无人确认，不得上线 |

| P7 | 人工确认凭据有效（`--approve all` 或 slug 列表） | **没人批就上线** |

1. **无清单时 P1–P7 全项 fail-closed**（不是"没数据就跳过"）—— 宁可拒，不靠缺数据蒙过。

   因为落线前的真正风险是「基线被别人改过，一上线就把别人的改动覆盖掉」。

## 关键实现选择（都是踩过坑才这么写的）

1. **预览用 `<iframe srcdoc>` 承载完整 HTML 文档**。指南正文本身就是「doctype + head(blue.css) + 正文」的完整文档，只有 iframe 才能 100% 还原站内渲染，且多国 CSS 互不污染；主页面不引入站点 CSS，样式完全可控。
2. **三件套一律注入 `content-section` 内部**。前端按章分页渲染、用硬编码骨架，只搬「匹配到的那一个章节」→
   放 `.nrz` 下或 `main-container` 顶层的元素会被整块丢弃（版本条曾整块消失），依赖注入 `<style>` 的样式也不生效（徽标曾空白）。详见规范 §11。
   > 旧结论「版本条被 `.nrz{display:flex}` 挤到页尾」**已作废** —— 那是本地整篇渲染的假象，线上从不整篇渲染。
3. **章节徽标走 `data-cg-badge` + CSS `::after`**。用 `<span>` 注入文字会被前端目录读进 TOC；**而且前端用 h2 文本做章节匹配**，塞文字会让匹配变脆。
4. **锚点用 `<h3 class="subsection-title">` 全串**，构建前必须断言唯一（`count==1`）。各国章节命名不统一（同一个「休假」有的叫 `休假政策` 有的叫 `休假政策（2026 年版）`），锚点必须逐国核。
5. **线上已有标注的国家必须先迁移、不能重建**。批次配置是从干净原文筛出来的子集，直接 `--apply` 会**回退**掉线上已存在但本批未覆盖的标注（阿联酋：线上 6 条 vs 批次 3 条）。`migrate_existing.py` 的反向还原校验保证反抽无遗漏。
6. **左侧目录「小气泡数字」只能走 CSS，碰不了 DOM** ★（2026-09-22 加）。前端 `TableOfContents` 组件收的是**整篇 content 字符串**，自己用 `/<h2[^>]*>…<\/h2>/gi` 扫章节，并且 `text = 剥掉所有标签后的纯文本`；渲染时只输出 `[纯文本, " ", 是否当前]`——
   **没有 data 属性、没有插槽、没有状态字段**。所以：往 h2 里塞 `<span>` 会被剥成裸文本；h2 的 `::after` 徽标不进 textContent，目录天然看不见；props 也没口子可传。**唯一挂载点 = `a[href="#heading-N"]::before`**（N 是 h2 全局序号，用 `toc_index_map()` 复刻前端规则，别用 `_sec_idx`）。
   三个必须记住的细节：
   - ① 伪元素要挂 **`::before` + `float:right`**。挂 `::after` 时，侧栏只有 160~180px 放不下「外企本地化与签证管理」，气泡会被挤到第二行悬在文字下方（很难看）；`::before` + float 让气泡锁在第一行右侧，长标题只让文本折行。
   - ② 这个 `<style>` 必须**每章注入一份**——它虽然作用于页面骨架，但页面按章渲染，缺了哪一章，那一章的页面上目录就一个气泡都没有。
   - ③ ★ **必须整块包在 `@scope (.table-of-contents){…}` 里，内部只用元素选择器**。平台会用 PostCSS 给 `<style>` 里的规则**自动加 `.article-isolate ` 作用域前缀**，而左侧目录在 `.article-isolate` 容器**外面** ⇒ 直接写 `.table-of-contents a[href=...]` 会变成 `.article-isolate .table-of-contents …`，**永远命不中**，线上表现是「样式块明明在、气泡一个都不出现」。
     实测逃逸规律（2026-09-22 用不存在的选择器做零影响探测）：**加前缀** = 类/元素/属性/通配/`:root` 开头全中，`@media`／`@layer`／`@supports` 块内也递归加；**不加前缀** = `@scope` 块内**以元素选择器开头**的规则（同块内以类开头仍会被加）。这是目前已知的唯一缝隙。

> ⚠️ **两列是"页面撤出、台账保留"的落点**（2026-09-23）：`更新时间` = 标注写入时间；`校对ID` = 台账主键兼页面 `data-cg-rid` 属性值。页面 F4 门禁保证它们不出现在客户视野里。台账 `_field_notes` 已逐条写明这层对应关系。

写入路径（全部经 `scripts/ledger_client.py`，唯一实现）：
① `make_ledger.py` 出 CSV（**人工导入**或脚本 upsert）；
② `verify_secondary.py --sync-ledger` 按**时机**分流写两组字段 —— `--source staging` 写 **二次校验三列**（落线前预验），`--source live` 写 **三次校验三列**（落线后回读）。两组各记，互不覆盖；
③ `release_apply.py` 回写**上线状态/上线确认人/上线确认时间/上架时间**；
④ 对话内直接 patch。

**状态口径**：`上线状态` ∈ {待上线, 已上线, 已退回}；「已上线」必须同时满足「上架时间有值 + 三次校验结果 ✅ 通过 + 上线确认人有值」。回滚 → 置「已退回」并在备注写原因与所用 ORIGINAL。

六个实测坑（照抄会省时间）：

| 坑 | 正解 |
|---|---|
| `--page-size` 报 unknown flag | 用 `--limit`（1–200） |
| `--format json` 的返回结构看不懂 | `data.fields`=字段名数组，`data.data`=行数组**按位对齐**，`data.field_id_list`=字段 ID，`data.record_id_list`=记录 ID **按位对齐** |
| 字段列表取不到名 | `+field-list` 的键是 `data.fields`（每项 `id`/`name`/`type`），不是 `items` |
| **建 select 字段报 `Unrecognized key(s): 'property'`** ★ | 用 `--json '{"name":"X","type":"select","multiple":false,"options":[{"name":"…"}]}'` —— 键是 **`options`**（不是 `property`），且 `--dry-run` **不做校验**，别信它 |
| 栅格字段名带空格（`QC 状态`）→ 报 `not_found` | 字段名逐字照抄，含空格。改字段名前先 `+field-get` |
| 删字段/改字段是高危，直接报 `confirmation_required` | 加 `--yes` |

改 select 选项的安全姿势（避免老记录值被清空）：**先加新选项并保留旧选项 → 批量更新记录到新值 → 再 PUT 去掉旧选项**。

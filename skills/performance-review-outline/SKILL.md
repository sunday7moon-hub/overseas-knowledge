# 述职 / 答辩 PPT 大纲生成

产出的是**页面级大纲文档（.docx）**，不是 PPT 本身。用户拿它做两件事：确认结构、照着填内容做 PPT。

## 工作流

### 1. 抽取历史素材（必做）

用户通常会给 2-3 份参考 PPT（往年规划、往年答辩、公司模板）。用标准库直接解析，**不要装 python-pptx**：

```python
import zipfile, re
from xml.etree import ElementTree as ET
NS = '{http://schemas.openxmlformats.org/drawingml/2006/main}t'
z = zipfile.ZipFile(path)
names = sorted([n for n in z.namelist() if re.match(r'ppt/slides/slide\d+\.xml$', n)],
               key=lambda n: int(re.findall(r'\d+', n)[0]))
for n in names:
    tree = ET.fromstring(z.read(n))
    for shape in tree.iter():
        if shape.tag.endswith('}sp') or shape.tag.endswith('}graphicFrame'):
            s = ''.join(t.text or '' for t in shape.iter(NS)).strip()
            if s: print('•', s)
```

**重点抓三类信息**：
- 个人档案：入职时间、部门岗位、职级、履历时间轴、认证资质、能力模型
- **已验证数据**：历史 PPT 里的数字可直接复用（如「获客成本 400→90 元」「矩阵号 1:2→1:18」），标为历史数据
- 版式语言：该作者惯用的章节页结构、方法论模型名、金句

模板 PPT 只需看前 5 页，确认章节页/内容页的版式节奏。

### 2. 问清汇报对象（决定性）

**不问清楚就开写，大概率返工。** 同一个岗位，汇报对象不同，大纲完全不同：

| 汇报对象 | 叙事主线 | 核心指标 |
|---|---|---|
| 业务销售总 | 我为销售增长提供什么弹药 | 线索量、分配时效、转商机率、物料交付时效 |
| 产品总 / 技术总 | 我有什么产品规划与落地能力 | 产品矩阵、架构、路线图、风险与需要的支持 |
| HR / 职能线 | 职责履行、学习成长、稳定性 | 培训完成率、项目交付、协同评价 |
| 双领导（汇报对象 ≠ 直属） | 分两条线，各给各的 | 见下方「双领导处理」 |

用户若没说，**先问再写**。

### 3. 确定页面结构

标准骨架（可按用户给的目录调整）：

```
P1 封面（主标 + 副标定位语 + 演讲者/日期）
P2 目录
前言：个人简介（3页）
  - 基本信息 + 岗位定位（★全篇锚点，写清「一岗N角色」）
  - 履历时间轴（每节点挂「能力沉淀关键词」）
  - 能力模型与资质
一、工作总结（章节页 + 8-12页）
  - 岗位主要职责及履行情况（表格：职责线 / 核心工作 / 履行情况数据）
  - ★ 业务价值全景（按对方业务链条挂你的支撑动作）
  - 参与的内部培训及完成情况（分集团/公司/业务三层）
  - 自主学习提升情况（专业技能 / 行业知识 / 方法沉淀 / 读书输出）
  - 核心任务总览（数据大字报）
  - 核心任务 ①-⑥（每条一页：痛点 → 动作 → 结果 → 方法论）
二、工作感悟（章节页 + 4-5页）
  - 收获与成长（用「从A到B」句式，4条）
  - 对岗位价值的理解（三层价值 + 核心公式）
  - 岗位优化建议（现状-问题-建议 三段式表格）
  - 对部门/公司建议
  - 可选：个人短板（主动说短板比只讲成绩更可信）
三、未来规划（章节页 + 6-9页）
  - 1年目标（主线定位 + 3-5个目标 + 量化表：当前值/目标值/衡量口径）
  - 关键行动（方向-关键行动-衡量指标 三层表）
  - 季度路线图（每季一个主题，挂3个里程碑）
  - 预期成果（分业务/效率/资产/个人四类）
结尾页（金句 + 致谢）
附录：素材清单 + 制作规范 + 待补数据清单
```

### 3.5 有时长限制时（必问：汇报几分钟？）

**不问就写会翻车。** 30 分钟述职，主线只能 20 页左右。压缩三板斧：

1. **合并同类页**：培训+自学、收获+岗位认知、优化建议+公司建议、定位+架构+矩阵、路线图+要资源+预期、预期成果+结尾。典型能压掉 8-10 页。
2. **明细页降为备查页**：履历时间轴、历史项目明细、流程规则详情、完整素材截图、全量产品矩阵、风险明细、数据明细表。放正文之后，用浅色分隔页标「以下为备查，供交流环节参考」。
3. **每页标时长**：输出节奏总表（页号 / 建议时长 / 累计时间 / 优先级 / 一句话讲什么）。优先级 `★★★必讲 · ★★重点 · ★快过 · ○可跳`。

配套三件事，缺一不可：
- **控场锚点**：选一个中段核心页（如最重要的案例页），标明「讲到这页应落在第 X 分钟」。
- **超时兜底**：3 个可压缩点（各标注省多少秒）+ 2 个可跳页。
- **绝对不能砍的页**（通常 3 页：定位页 / 核心案例页 / 要资源页）—— 这是全篇骨架。

时间配比参考（30 分钟）：开场定位 3 分钟、工作总结 14 分钟、感悟 4 分钟、规划 7 分钟、结尾 1 分钟，留 1-2 分钟缓冲。

**别用传统目录页**：改「三句话」全篇预览（做了什么 / 想明白什么 / 接下来做什么），30 秒说清主线。

### 4. 双领导处理（汇报对象 ≠ 直属领导）

这是最容易翻车的场景。做法：

- **封面副标**同时体现两条线
- **岗位定位页**写清汇报关系，用「一岗N角色」，前几个是已交付价值，最后一个是**要争取的方向**
- **内容页标注受众**：用 `★（销售总重点看）` / `★（产品总重点看）` 显式标注
- **篇幅比 2:3**：先证明「我能交付业务价值」（占大头），再争取「让我做新方向」（占小头）。先立功，再要资源
- **规划部分对新方向给足篇幅**：定位与架构 → 产品/方案矩阵 → 路线图 → 预期收益与风险。四页连讲
- **敢开口要支持**：路线图页底部单列「需要的支持」（资源/数据/配合），比空喊目标可信

### 5. 生成 docx

用 python-docx（环境：`/Users/yoyo/.workbuddy/binaries/python/envs/default/bin/python`，已装）。

**中文字体必须设 eastAsia，否则中文会掉回宋体**：
```python
run.font.name = 'Times New Roman'
run._element.rPr.rFonts.set(qn('w:eastAsia'), 'PingFang SC')
```

配色沿用用友薪福社/Humance 蓝：主蓝 `#123b7a`，次蓝 `#1f4f8f`，强调红 `#c0392b`，灰 `#6b7280`。

**坑**：辅助函数签名若含 `level` 参数，传颜色必须用关键字 `color=RED`，否则 `B(text, RED)` 会把颜色塞进 level 导致 `TypeError: can't multiply sequence`。

### 6. 数据占位规则

- 所有未验证数字写成 `X`，不编造
- **历史数据（往年 PPT 已验证）与本期数据分区呈现，不混用**——这是述职最容易翻车的地方
- 每个数字标注口径与时间范围
- 末尾附「待补数据清单」，按优先级列出要用户确认的项

### 7. 直接改已有 PPT（用户已有成稿时）

用户常已有接近定稿的 PPT，只想补几页。这时**不要重新生成全篇**，在原文件上插入即可。环境：
`/Users/yoyo/.workbuddy/binaries/python/envs/default/bin/python`（python-pptx 1.0.2 已装）。

**做法五步**（可复跑脚本见 `outputs/build_review_ppt.py` 模式）：

1. **提设计 token**：先遍历目标页所有 shape，打印 `fill.fore_color / font.size / font.bold / font.color / font.name` 和坐标，把配色、字号、栅格（左右边距、卡片宽、行距）抄下来。新页必须沿用，不能自创。
2. **克隆母本页**：挑一个结构最接近的现成页面，深拷贝其 XML（`deepcopy(shp._element)` 追加到新页 `_spTree`），这样背景、logo、页脚等装饰全部继承。
3. **清空内容区**：按坐标判断保留项（全屏背景 `w>13 且 h>7`、logo `shape_type==13`、标题竖条、页脚 `y≈7.14`），其余 `shp._element.getparent().remove(...)`。
4. **重画内容 + 移动位置**：用保留的 token 画新内容；`move_slide()` 操作 `prs.slides._sldIdLst` 把新页插到目标位置。
5. **顺延页码**：遍历定位到页脚页码文本框（按坐标匹配），清空 runs 后重写 `"{i:02d} / {total}"`。注意封面/章节页可能没有页脚，属正常。

**三个必踩的坑**：
- 克隆页含图片时，必须手动重建关系，否则 logo 丢失：
  `blip.set(qn('r:embed'), new_slide.part.relate_to(src_slide.part.related_part(rId), RT.IMAGE))`
- 中文字体光设 `font.name` 不够，要补 `a:ea`，且必须用 `latin.addnext(ea)` 插入以保证 schema 顺序正确。
- 文本框默认自动溢出不裁剪，所以"文字超框"不会报错但会挤到相邻元素——必须事先算高度。

**无 CLI 转换器时的校验**：macOS 常没有 LibreOffice，`soffice` 不可用。改用两步自检：
- 坐标越界：遍历 shape 算 `top+height`，标记超出内容区底部的；
- 文字溢出：按「中文/CJK 全角 = 1.0em，半角 = 0.55em」估算每行宽度 → 换行数 → `行数 × 字号 × 1.28` 对比框高。
  该估算偏保守，原 PPT 也会报一堆告警，只要**新页不比原页更差**即可判定通过。

## 输出

写入 `outputs/YYYY-MM-DD <公司/项目>述职报告（续签）大纲_vN-<视角>.docx`。

迭代时**保留旧版本**并生成 vN+1，文档开头放「vN 相对 vN-1 的调整说明」对照表——用户偏好变更对照，便于回看取舍。

## 呈现原则

- 给业务领导：多用 before→after 对比，少讲过程多讲结果，每页都能回答「这给业务带来了什么」
- 结构性调整时直接生成新版本，不要在原文档上打补丁
- 正文末尾附「待补数据清单」，并主动提议下一步（取数 / 生成 PPT 初稿）

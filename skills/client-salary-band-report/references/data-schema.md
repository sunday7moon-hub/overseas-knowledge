# 数据输入契约（Data Schema）

新任务开工前，先按本表收齐输入。缺哪一项，就先要哪一项——**不要用编造数据补位**。

---

## 一、必填输入（不收齐不开工）

| # | 字段 | 说明 | 缺失后果 |
|---|---|---|---|
| 1 | 客户 | 简称 + 全称（简称用于页眉/文件名/元数据） | 无法命名交付件 |
| 2 | 岗位 | 中文名 + 英文/缩写 + 是否 IC/管理岗 | 无法定章节标题 |
| 3 | 国家/城市 | 驻地城市（决定币种与社保口径） | 汇率与合规口径无从锁定 |
| 4 | 报告类型 | 单国单岗（`make_single_report`）／多国分地区（`make_region_report`） | 选错模板会白做 |
| 5 | 薪资带宽 | 至少 3 档：经验档 + 基础下限/上限 + OTE 下限/上限 + 市场分位 | 核心交付物为空 |
| 6 | 汇率 | 使用当日的 CFETS 中间价口径 | 三币换算失真 |

## 二、选填输入（有则更好，提升可信度）

| 字段 | 用途 |
|---|---|
| 候选人报价 | 触发「候选人报价校准」章；无则整章跳过（`CANDIDATE = None`） |
| 宏观基准 | 最低工资、平均月薪、社保率、个税率 → 「市场基准」章 |
| 驻地要点 | 签证门槛、外籍配额、生活配套 → 「驻地与用工要点」章 |
| 年成本口径 | 成本指数（以某驻地 = 100）→ 多国总览表 |

## 三、字段数据结构

### 3.1 单国：分档带宽 `BANDS`

```python
# (经验档, 基础下限, 基础上限, OTE下限, OTE上限, 市场分位)
BANDS = [
    ('5-8 年（入门）',    70000,  95000,  84000, 118000, 'P50-P65'),
    ('8-12 年（推荐档）',  95000, 130000, 114000, 162000, 'P60-P75'),
    ('12-18 年（资深）',  130000, 175000, 156000, 218000, 'P70-P85'),
    ('18+ 年（稀缺）',    175000, 230000, 210000, 287000, 'P80-P95'),
]
RECOMMEND_INDEX = 1          # 推荐档下标，摘要与 callout 取这一档
```

### 3.2 多国：国家行 `COUNTRY`

```python
# (国家, 币种, 基础下限, 基础上限, OTE下限, OTE上限, 分位, 成本指数, 驻地定位, 综合建议)
COUNTRY = {
  'gulf': [
    ('沙特（利雅得）', 'SAR', 32000, 40000, 38000, 52000, 'P60-P75', 100, '基准驻地', '推荐'),
  ],
}
```

国家名必须**同时**出现在 `COUNTRY` 与 `EXTRA`（驻地要点）里，且字符串完全一致；
表格显示用 `name.split('（')[0]` 取短名，`EXTRA` 索引用全名。

### 3.3 币种代码与汇率 `RATES`

`RATES = {'CUR': (→CNY, →USD)}`，基线为 2026-09-01 CFETS 中间价。
新报告开工时用 `set_rates({...}, basis='<当日口径>')` 覆盖，**一份报告内锁定同一组**。

新增币种前先确认它有 ISO 代码可用（**小币种符号如 ₩₺₽₹฿ 在 SimHei 与 Helvetica 都无字形，只能写代码**）。

## 四、四条硬口径（违反即返工）

1. **三币并行**：本币为主，另给 ≈¥ / ≈$。窄列用 `CU2()` 分行，宽列用 `CU()` 并列。
2. **汇率表禁用取整函数**：`rates_table()` 内部走 `Cx()/Ux()`。
   用 `C()/U()` 会把 IDR/THB 等换 1 单位时抹成 `¥0`（2026-09-14 P0 事故）。
3. **同一报告单一汇率日**：三栏换算必须同源同日，不得混用。
4. **GROSS 口径必须显式声明**：税前/税后差异在无个税国家（海湾）与累进国家之间影响巨大。

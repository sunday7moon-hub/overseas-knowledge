# 客户事实表（Client Facts）— 防转述丢失的单一真相源

**为什么有这个文件**：报告口径出错的根因几乎从不是「查不到数据」，而是**客户给的事实被复述、被转手、
在重构中被改窄**。事实一旦被复制成多份副本，就必然出现漂移。

2026-09-14 控维事故：客户要求「候选人 8-15 年工作经验」，报告却写「10-15 年主力经验档」——
客户最初诉求本来就是 8-15 年，是重构 v4/v5 时被写窄的。**没有任何门禁盯着客户原话，所以两周无人发现。**

所以规则是：**客户说什么，逐字记在这里，不在别处复述。**

---

## 一、使用规则（三条，不遵守则本文件失效）

1. **逐字留档**：记客户原话，不记我的概括。原话是「8-15 年」，就写「8-15 年」，
   不许改写成「十年以上」或「资深」——**复述环节就是丢失环节**。
2. **先改本表，再改代码**：任何口径变更（经验档、国家清单、锚点、岗位名、结构比例），
   必须先在「事实断言」块里改断言，再改脚本常量，最后重产报告。顺序反了就会漏。
3. **开工第 0 步读本表**：新会话 / 新 Agent 接手，第一件事是读本表 + `SKILL.md` 冷启动段，
   **不是**读历史对话（对话里的口径可能是过期版本）。

> 本表存**客户确认的事实**；脚本常量存**实现**；`SKILL.md` 存**机制**。
> 三者关系：本表是真相源，脚本必须与之一致，门禁负责证明一致。
> **不要把这里的数字抄进 memory**——memory 只记「真相源在哪」和「这里踩过什么坑」。

```facts
!10-15 年主力经验档 | 控维

!以色列 | 东南亚
!印度尼西亚 | 中东

!新加坡 | 中东
# 交付合规
用友薪福社 | *
```

> 说明：`!10-15 年主力经验档` 是**这次事故的直接防复发断言**——旧标签一旦回潮立即 FAIL。
> 注意**断言要写「旧标签的确切整串」，不要只写 `10-15 年`**：正文里「其中 10-15 年为市场供给
> 最密集段」是合法表述，写宽会误伤自己（本文件首次编写时就踩了这个坑）。
> 原则：**断言 = 客户原话里那个易错的确切字符串，一个字不多不少。**
>
> 匹配为**去空白比对**（PDF 提取常在换行处断开，如「8-15」与「年主力经验档」分属两行），
> 因此空格与换行不影响断言，无需在断言里迁就排版。

## 四、新增客户时怎么用

1. 复制第二节的骨架，改成新客户；
2. 把客户原话逐字填进「已确认事实」表（拿不到原话就先留空，不要猜）；
3. 在「事实断言」块写 2-5 条**最容易被写错的**断言——优先写：
   - 经验档 / 分位口径
   - 国家清单与地区隔离（反向断言成对写）
   - 岗位名与锚点
4. 交付前：
   ```bash
   python $S/scripts/content_lint.py *.pdf \
     --facts ~/.workbuddy/skills/client-salary-band-report/references/client-facts.md --strict
   ```

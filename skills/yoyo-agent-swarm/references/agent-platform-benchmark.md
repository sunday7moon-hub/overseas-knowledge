## 〇、一句话结论

| 产品 | 定位 | 一句话 |
|---|---|---|
| **Accio Work** | 团队编排型 · 跨境生意 | 唯一把「多 Agent 团队 + 技能自动沉淀」做出来的，架构最值得抄 |
| **Qoder** | 个人执行型 · 中文办公 | 中文交付最强、环境自修复最好，但多 Agent 协作是短板 |
| **Codex** | 并行工程型 · 软件开发 | 多 Agent 并行 + Git 隔离的工程实现最扎实，自动化后台跑不依赖本机 |
| **WorkBuddy** | 全能工作台 · 中文职场 | 你手上的平台：中文场景最贴、专家池最厚，但编排与稳定性是缺口 |

**对你的 Agent Manager：架构抄 Accio，工程抄 Codex，运营抄 Qoder，质检在 WorkBuddy 上补。**

**四个产品没有一个同时占住「强编排 + 强本地 + 强中文交付」——这就是你的机会窗口。**

## 一、Accio Work：团队编排型（阿里国际）

### 1.1 配置模式六层

| 层 | 设计 |
|---|---|
| **创建四步** | 选模板 → 身份与模型 → 工具与工作区 → 技能 → 用户信息 |
| **工具 4 档** | Standard / Full / **Minimal 只读（Reviewer 模板）** / TL（额外获团队管理权） |
| **技能三层** | Agent 级 > 账户级 > 内置；市场 116 个，分 7 类 |
| **权限** | 四级模型（自动批准/每次询问/记住选择/始终拒绝）+ 会话级能力集 + 目录白名单 + 符号链接逃逸检测 |
| **自我进化** | **SkillHarvest**（v0.13）从执行轨迹自动收割 skill；Agent 复制克隆 |
| **协作** | **Team Mode**（v0.14）：TL 派活 + **结果验证机制** |

**关键设计（值得直接抄）**：
- 官方文档原话："**描述不只是给你看的。TL 用每个成员的描述来决定谁领什么任务。**" → 角色描述是**机器可读的路由信号**，不是装饰文案
- **只读是一个正式档位** → 你的 QC Auditor 就应该长这样：Minimal 只读 + 无写入权 + 只产出判断
- **浏览器子 Agent 遇登录墙立即停、禁止自动登录** → 停 + 报，不硬闯

### 1.2 优劣势

**优势**：多 Agent 编排最成熟 / SkillHarvest 自动沉淀 / 只读档位 / 定时任务**断网可用 + 重启补跑** / 多模型按 Agent 分配 / 渠道最全（Telegram·Discord·微信·钉钉·飞书，支持多实例）/ 权限粒度最细 / 技能可变现

**劣势**：**生态锁定严重**（不做阿里供应链则价值急剧下降）/ **外部集成是半成品**（Gmail OAuth 直接报 400、Shopify 报错、商品上架产出空白草稿还照扣积分）/ 积分消耗不可预测且不结转 / 营销内容是弱项 / 协作慢到不可用 / 移动端只支持绑一个机器人 / 2026-03 发布太新，团队模式仍 Beta

## 二、Qoder：个人执行型（阿里云）

### 2.1 配置模式

- **产品矩阵**：Qoder IDE / QoderWork（本地桌面）/ QoderWake（数字员工，私有云）/ Qoder Mobile / Cloud Agents
- **岗位化**：专家套件按岗位打包（法律·产品·合同·投研·财税等 10+ 行业）+ 技能市场
- **QoderWake 三件套**：角色文档 + 权限边界（默认无生产环境权限）+ 高危操作拦截/二次授权；内置 10 个岗位
- **任务式交互**：目标 → 拆解步骤 → 产出文件 → 任务留存可回溯/续跑/监控；任务监控区显示待办步骤、产物、调用的技能与 MCP
- **意识功能**（2026-06-16）：分层记忆（Markdown 存本地可编辑）+ 反思（快照备份 + 硬规则校验 + 越界回滚）+ 技能进化（Fork Session，缓存命中 99%+，额外成本 <5%，**生成建议但不直接入库，需用户确认**）

### 2.2 优劣势

**优势**：本地数据安全叙事最强 / **环境自修复**（缺 Node.js 自己装、缺 Python 写 PowerShell 顶上、自查 UTF-8 BOM）/ 关键决策节点主动停下确认 / 中文办公交付质量最好（网页实测 8 分）/ 钉钉 2600 万组织资源 / 10 万+ 员工内部验证 / 岗位化最彻底 / 免费额度友好 / 效率数据亮眼（竞品调研 2天→11分钟）

**劣势**：**定时任务必须电脑不睡，关屏即失效**（最致命）/ **多智能体协作能力缺失**（工信部报告点名"显著差距"）/ 7.5 分实习生天花板（缺 Logo、模板残字 "05 I am the chapter name"）/ **事实核验硬伤**（写出无来源的"每年 10 亿美元"）/ 第三方评测指文件内容实际需上传服务器，与官方叙事有落差 / 版本仅 0.5，长任务 BUG 多 / 平台覆盖弱 / 赢了赛马没拿到组织主导权

## 三、Codex：并行工程型（OpenAI）

### 3.1 配置模式

| 层 | 设计 |
|---|---|
| **发布** | 2026-02-02 macOS app（Apple Silicon），**2026-03-04 Windows 版** |
| **模型** | GPT-5.3-Codex（2026-02-05）；SWE-bench Pro 57%、TerminalBench 2.0 76%、OSWorld 64%；上下文 400K / 输出 128K |
| **多 Agent 并行** | 每个线程独立沙箱 + **内置 Git worktrees**，多 Agent 同时操作同一仓库不冲突——**这是它真正的差异化点** |
| **Skills** | 指令+资源+脚本打包；Figma / Linear / Vercel / Netlify / 图像生成 / 文档；可显式指定或自动选用；有独立创建与管理界面 |
| **Automations** | 定时后台任务（issue 分诊、bug 检测、CI 监控、日志抓取、测试修复），**结果进 review queue**，人只看队列 |
| **Plan Mode** | 执行前先讨论策略、提出替代方案、等批准 |
| **Git 内置** | Diff 审阅、行内评论、stage/revert、worktrees |
| **沙箱** | 限定文件夹/分支；**网络访问与 shell 命令需显式批准**；CLI 为 Apache-2.0 开源 |
| **Codex Cloud** | 异步：克隆到隔离容器，跑 10-45 分钟交付 PR；**容器访问不到本地机器、密钥、生产系统** |
| **人格模式** | /personality 切换 Terse/Pragmatic 与 Conversational/Empathetic |
| **企业版** | Slack bot、GitHub Actions、PR 里 @Codex 触发评审 |

### 3.2 优劣势

**优势**：
1. **多 Agent 并行 + 隔离最扎实**——worktree 让并行任务零冲突，工程实现上比 Accio 的 Team Mode 更硬
2. **自动化真后台跑**——云端执行，不依赖本机唤醒（与 Qoder 形成鲜明对比）
3. **结果进审核队列**——人只在需要时介入，不盯过程
4. **沙箱默认严格**——网络/shell 需显式批准；开源 CLI 可审查
5. **Plan Mode + Diff 审阅 + 行内评论**——审批链路完整
6. **捆绑定价**——ChatGPT Plus $20 即含，试用门槛最低
7. **开源可审计**——CLI Apache-2.0，Codex SDK + GitHub Action
8. 官方称 30 分钟自主工作；内部用它加速了 5.3-Codex 自身开发

**劣势**：
1. **使用量上限是最大抱怨**——Plus 每 5 小时仅 30-150 条消息，重度用户两小时就触顶；Pro $200 也有更严限制
2. **YOLO 模式是危险品**——`--dangerously-bypass-approvals-and-sandbox` 移除全部限制，可删文件、访问网络、改系统
3. **长对话性能退化**——每轮带全量历史，提示词二次增长，会话越长越慢越贵
4. **平台限制**——桌面版仅 Apple Silicon，Intel Mac 不支持（Windows 版 2026-03 才上）
5. **纯英文开发向**——无中文办公优化，非开发场景基本用不上
6. **数据上云**——云端沙箱模式数据进 OpenAI 基础设施
7. **模型锁定**——只有 OpenAI 自家模型
8. SWE-bench 69.1% 略低于 Claude Code 72.7%

## 四、WorkBuddy：全能工作台（腾讯）— 你手上的平台

### 4.1 配置模式

| 层 | 设计 |
|---|---|
| **出身** | 腾讯云 CodeBuddy 团队，2026-03-09 推出，2026-03 公测；2000+ 腾讯员工内测 |
| **定位** | "全场景 AI 桌面智能体"——一句指令直接交付**可验收结果**，不是给建议 |
| **技能** | 20+ 内置技能（Excel / PPT / 深度研究 / 邮件 / 代码 / 游戏 / 网页自动化 / 图像 / 文档）；用户可自行安装 skill |
| **专家** | **12 大领域、140+ 行业顾问**；可召唤多专家**互相 review**（如架构师 + 后端工程师互审方案） |
| **自动化** | 定时任务可用，实测确实按时触发（项目进度追踪 / 周报素材收集 / 写作打卡等模板） |
| **远程** | 微信直连，手机发指令电脑干活；支持微信 / 企业微信 / 飞书 / 钉钉 |
| **模型** | 腾讯自研 Hy3 + GLM-5.2 / DeepSeek / MiniMax；**无法自定义接入 GPT / Claude** |
| **工作记忆** | 跨会话长期记忆（需主动维护，否则积累过时信息） |
| **安全** | 本地运行，数据留本机；**需授权文件夹，不授权不动** |
| **商业化** | 免费 5000 积分起步 |

### 4.2 优劣势

**优势**：
1. **中文职场场景最贴**——Word / PPT / Excel 中文交付，非技术背景零门槛
2. **专家池最厚**——140+ 行业顾问，且**支持多专家互相 review**（这是天然的 QC 层，很多人没用起来）
3. **微信直连远程控制**——手机一句话触发，四个产品里唯一的中文 IM 深度打通
4. **本地运行 + 授权文件夹**——数据留本机，且默认不乱翻
5. **多模态一体化**——文字/图片/视频在同一对话完成，不切工具
6. **工作记忆跨会话**——解决"金鱼记忆"
7. 免部署，下载即用

**劣势（实测翻车记录，都是真实边界）**：
1. **跨应用操作不行**——无法访问微信/企业微信/QQ 发消息（"把文档发给微信助手"直接失败）
2. **复杂任务卡顿/卡死**——"写 1000 字报告 + 配图"报 too many requests；复杂多步骤任务易中途卡死
3. **初稿质量不稳**——会生成"彩虹屁"式不客观内容，需二次指令纠正
4. **积分消耗快**——几个任务 5000 积分见底
5. **稳定性**——偶尔掉线；微信里 Markdown 渲染差
6. **格式兼容**——Pages 等文档读取失败
7. **模糊指令理解偏差**
8. **模型不可自定义**——用不了 GPT / Claude
9. **无真正任务编排**——多专家是"会诊"，不是"派活 + 结果校验"

### 4.3 专家调用环节：模型限制规则（成本受控）

> Yoyo 2026-09-09 定，已写入 `yoyo-agent-swarm/SKILL.md`（唯一真相源）。

**问题**：专家是"叠加在基础模型之上的角色"。主会话跑强模型时，专家调用会按强模型单价计费——**这是四款产品里 WorkBuddy 特有的 credit 黑洞**，也是实测中"积分消耗快"的主因之一。

**规则**：调用 WorkBuddy 专家（Expert）时，模型强制锁定低耗档，并按级联自动降级。

**档位级联（2026-09-09 补充第二版）**：

| 档 | 模型 | 触发条件 | 请示 |
|:-:|---|---|---|
| 1 | `Hy4 preview` | 默认首选 | — |
| 2 | `Hy3` | Hy4 preview **排队中 / 繁忙 / 不可用 / 连续超时** | ❌ **自动切** |
| 3 | 平台标注「**限时免费**」的当前可用模型 | 档 1、2 均不可用 | ❌ **自动切** |
| 4 | 主会话模型 | 兜底 | ❌ 自动，须记日志 |
| ↑ | 强模型 | 例外升级（长上下文 / 深度多步推理 / 复杂代码 / QC 复核 / **降级后产物不达标**） | ✅ **须写理由 + 记日志** |

> **核心原则：降级自动不请示，升级必须有理由。**
> 排队等待 = 空耗时间不省 credit，不如降级跑完；升级花的是真金白银，必须留痕。
>
> 执行细则：判定信号为「排队中/繁忙/稍后再试/达并发上限/30 秒无响应」→ 立即降一档重试，最多降两档；降级须在产物中标注 `模型降级：Hy4 preview → Hy3（原因：排队超时）`；**降级不降低验收标准**，若 QC 判 P0/P1 且疑似模型能力不足，允许按例外升级重跑一次。

**为什么省的是 credit 不是能力**：锁档后角色定义、专家知识、工作流全部保留，变的只是底层推理单价。

**三种落地写法**：
1. **子代理派发** → prompt 显式带 `【模型】Hy4 preview（专家调用成本受控）`
2. **自动化任务** → `expertId` 参数不带模型位，模型要求写进 `prompt` 正文第一行
3. **创建/修改专家包** → 走 `expert-manager`，在专家说明中标注默认档位

**校验**：派发前自检 prompt 有没有 `【模型】` 行；A7 运维巡检官抽查近 7 次专家调用，未锁模型即告警。

| **平台** | macOS + Windows | macOS 优先 | macOS(ARM) + Windows | 桌面常驻侧边栏 |
| **成熟度** | 新（2026-03），团队模式 Beta | 版本 0.5 | GPT-5.3-Codex，100 万+ 开发者 | 2026-03 公测 |

## 六、对 Agent Manager 的落地输入

### 6.1 分头抄什么

| 抄谁 | 抄什么 | 落地动作 |
|---|---|---|
| **Accio** | Agent 配置四步 + 只读档 + 描述即路由 + TL 派活与结果校验 | 岗位说明书补「工具白名单」「工作区路径」两栏；QC Auditor 改只读档；职责写"动词+对象+可判定边界" |
| **Codex** | **Automations + review queue** | 自动产出不直接推，先进**待审队列**，人只看队列不盯过程——这能直接解决你"每天盯着 cron 跑没跑"的问题 |
| **Codex** | **并行隔离（worktree 思路）** | 多 Agent 同时写飞书表/数据库时，给每个 Agent 独立工作区或独立视图，避免互相覆盖 |
| **Codex** | Plan Mode | 报告/长文/方案类先出大纲确认 |
| **Qoder** | 岗位说明书三件套 + 先内部跑通再外溢 | 已有 4 份岗位说明书，继续执行 |
| **WorkBuddy** | **140+ 专家互审** | 明确配成"专家 A 产出 → 专家 B 复核"的链路，把会诊变成流程化的 QC |

### 6.2 四个反面教材（别踩）

| 坑 | 出处 | 你的防线 |
|---|---|---|
| **YOLO 全放行模式** | Codex | 绝不提供"跳过所有审批"开关；高危操作必须二次授权 |
| **用量上限让重度用户干不了活** | Codex（Plus 两小时触顶） | 配额设计要让一天的量跑得完，否则自动化形同虚设 |
| **长会话性能退化** | Codex（历史全量二次增长） | 长链路任务拆段 + 中间态外存，不要一个会话跑到底 |
| **复杂任务卡死 + 初稿质量不稳** | WorkBuddy（too many requests、"彩虹屁"） | 加失败自动重试 + 超时告警；初稿必须过质检清单 |

### 6.3 共同的坑（四家都没解决）

| 坑 | 实例 |
|---|---|

### 6.4 你的机会窗口

**没有一款同时占住「强编排 + 强本地 + 强中文交付」。**

- Codex 强编排但云端、纯英文
- Accio 强编排但绑死阿里供应链
- Qoder 强中文但编排弱
- WorkBuddy 强中文、强本地但编排弱、稳定性待提升

你在 WorkBuddy 上做 Agent Manager，补的正是**「中文场景 + 本地数据 + 真正的派活与结果校验」**这一格。

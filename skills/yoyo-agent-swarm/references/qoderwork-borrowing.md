# QoderWork 借鉴维度（Design Borrowing Reference）v2

> **用途**：把阿里 QoderWork / QoderWake（2026-09-08 v1.0 数字员工）可迁移的设计机制，对照到 `yoyo-agent-swarm`（A1–A15）现状，形成**差距诊断 + 演进路线**。
> **性质**：诊断参考，**不改动现有路由与门禁**。落地建议均标注阶段，须 Yoyo 确认后执行。
> **权威事实源**：`~/.workbuddy/notes/ali-qoder-benchmark.md`（2026-09-08 Yoyo/巴蒂调研归档，引用事实以此为准，勿用本文件的二手转述替代）。本文件 v1（2026-09-09 公开报道重建版）已被本版取代。

---

## 0. 一句话对标

> 阿里把 Agent 当**员工**管：**先定义岗位（JD），再给权限**；用**权威数据源换掉模型编造**；高危操作**默认无权限 + 拦截 + 二次授权**；最后**内部跑通再对外卖**。
> 反面对照：QoderWork 内部指标第一（日活/周活/Token 集团第一），07-02 仍被整编进「千问办公」——**产品赢了赛马，不等于拿到组织主导权**（阿里云+钉钉手握 2600 万企业组织与交付网络）。→ 我们需主动给 Agent 群配「能力清单」，避免在组织内无归属。

## 1. 借鉴维度对照表（治理机制层：怎么把 Agent 当员工管）

| # | 借鉴维度 | 阿里怎么做的（QoderWork/QoderWake） | 我们现状 | 差距判定 |
|:--:|---|---|---|---|
| 1 | **岗位 = 角色文档三件套** | 一句话描述岗位 → 生成**角色文档（职责/协作关系/权限）** → 确认上岗；权限默认无生产环境 | registry 有 A1–A15 卡片（禀赋/上下文/门禁），缺**成文角色文档**与**权限边界（默认无生产权限）**声明 | 🟡 有骨架缺三件套 |
| 2 | **权限边界 = 默认无生产权限** | 数字员工默认无生产环境权限；高危操作拦截 + 二次授权 | 有「只读/不回写」原则 + 数值变更须确认，**高危动作清单未成文** | 🟡 有原则缺清单 |
| 3 | **权威数据换编造** | 内置企查查 MCP（3.65 亿+主体、T+0、结构化、省 Token）= 给 Agent 装可信数据源 | 有六层来源优先级 + 一票否决清单，但**数据层未服务化**（MCP 化前置两个 bug 未修） | 🟠 规则有服务无 |
| 4 | **人在环上 / 过程可控** | 本地优先：文件不出本机、仅访问授权文件夹、删除可恢复、**每步可追溯/可续跑** | 结果级飞书日志有；**过程轨迹与断点续跑无** | 🟠 无过程审计 |
| 5 | **五维沉淀（Harness）** | 任务记忆/技能库/执行策略/校验规则/工作流 五维沉淀，越用越准 | 技能库(L0–L4)✅ 记忆(memory)🟡 校验(QC)✅ 工作流(SKILL)✅；**执行策略缺失 + 跑完不自动回写** | 🟠 四维有维无环 |
| 6 | **角色上岗标准** | 岗位有明确产物标准（输入→产物→红线） | 各 Agent 有质量门禁，但**无"角色级合格线"**（做到什么算 OK、谁验收） | 🟡 |
| 7 | **数字员工矩阵化叙事** | 10 岗位预设 + 岗位说明书对外可讲"团队" | 15 Agent 讲的是脚本/cron，**缺一页纸岗位说明书**（对外/排障定位用） | 🟡 |
| 8 | **组织归属意识** | 反面教训：产品赢了赛马输了组织 | Agent Manager 只有飞书日志，**无「能力清单」同步给产品侧** | 🟠 需补 |

## 3. 差距诊断（按严重度）

### 🔴 结构性（不做到不了"数字员工"）
1. **过程可追溯/可续跑（维度4）**：QoderWork 强项之一；我们子任务中断即丢（2027 假勤丢数据即实证）。
2. **权威数据服务化（维度3/方向2）**：是护城河，但被两个未修 bug 卡死。

### 🟠 重要（影响规模化、可信度、组织地位）
3. **角色文档三件套 + 默认无生产权限声明（维度1/2/6）**：registry 补齐"职责/权限边界/合格线"。
4. **五维沉淀闭环（维度5）**：跑完一轮自动提炼 → 回写执行策略。
5. **能力清单给产品侧（维度8/组织提醒）**：避免重演 QoderWork 的组织结局。

### 🟡 快速补齐（文档级，1–2 周）
6. A1–A15 一页纸岗位说明书（对外/排障定位）。
7. 高危动作清单 + 二次授权流程成文。

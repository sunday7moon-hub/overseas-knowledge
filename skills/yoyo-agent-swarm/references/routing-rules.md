## 2. 任务拆分（Decomposition）

### 2.1 拆分四问
1. **目标是否可验证**：不可验证 → 先与 Yoyo 对齐验收标准
2. **是否跨 Agent**：跨 Agent → 拆成独立子任务，明确输入/输出契约
3. **是否有强耦合**：A1↔A2 同表 → 强制串行；其余可并行
4. **是否有前置依赖**：无数据则先跑采集，再跑校验/推送

### 2.2 拆分输出格式（每个子任务一张卡）

```yaml
- task_id: T1
  name: 采集今日出海资讯
  agent: A1
  depends_on: []
  input: 搜索词范围 / 目标条数 / 分类配比
  output: 飞书记录 ≥8 条可推送 + 入库 API
  gate: 14项校验通过 + PR六层拦截 + 三分类全覆盖
  timeout: 60min
```

### 2.3 并行度规则
- A1 与 A4/A5/A6/A7 可同时派发
- A2 必须等 A1 完成
- A3 可独立于 A1/A2（抓站源），但若要求"用今日新采集内容"则需等 A2
- 同一 Agent 一次只接一个子任务，串行排队

## 3. 派发方式（Dispatch）

### 3.1 用 Agent 工具启动子代理（推荐）

```
Agent(
  subagent_type: "general-purpose",
  description: "A1 出海资讯采集",
  prompt: """
  你是 A1 出海资讯采集官。
  必读上下文：~/.workbuddy/skills/yoyo-agent-swarm/references/agent-registry.md 中 A1 条目
  必读技能：~/.workbuddy/skills/overseas-news-daily/SKILL.md
  【本次任务目标】<填入子任务卡>
  【验收门禁】<填入 gate>
  【输出要求】返回：实际入库条数 / 拦截条数 / 分类分布 / 失败原因（如有）/ 关键文件路径
  全程用中文，结论先行。
  """
)
```

### 3.2 无需新建进程的轻量任务
直接由巴蒂执行（如改一个字段、跑一次脚本），不派子代理。

### 3.3 环境前置（所有飞书/网络操作必做）
```bash
unset http_proxy https_proxy HTTP_PROXY HTTPS_PROXY
export no_proxy="*" NO_PROXY="*" LARK_CLI_NO_PROXY=1
```

## 4. 结果分拣（Triage）

子代理返回后，巴蒂按三步分拣：

### Step 1 — 完整性分拣
| 判定 | 处理 |
|------|------|
| 输出齐全 + 门禁全过 | → 汇入「已完成」 |
| 输出齐全但门禁未过 | → 汇入「待返工」，附具体未过项，重派一次（最多 2 次） |
| 输出缺失/报错 | → 汇入「失败」，记录错误栈 |
| 无报错但数据可疑（数量异常/内容空洞/来源存疑） | → 汇入「疑似静默失败」，**强制转 QC Auditor** |

### Step 2 — 静默失败识别（重点）
命中任一即判静默失败：
- API 返回 `result:ok` 但查询不到数据（如 JSESSIONID 过期）
- 声称写入 N 条，实际表里只查到 M 条（M < N）
- 产出文件存在但内容为空 / 为占位符（`system-error-try-again-*`）
- 重复执行产生同 ID 重复记录
- 分类分布严重偏离（如某分类为 0）

### Step 3 — 交叉一致性
- 飞书条数 vs API 入库条数 是否一致
- 资讯 ID 是否连续不跳号
- 飞书侧 ID 与 Anchor Tech DB 侧 INFO_ID 撞号 → DB 侧另选未占用号

## 6. 强制转 QC 的六类情形

1. 连续 2 次返工仍未过门禁
2. 判定为疑似静默失败
3. 涉及**对外发布**且任一校验项未过 —— 对外发布清单：
   - A3 早报推飞书群、小红书素材
   - A9 客户向薪酬报告（含水印版）
   - A11 客户触达邮件（群发前必检）
   - A13 对外物料（客户/社群用图）
   - A14 对外商业计划书 / 方案文档
4. 数据源真实性存疑（来源打不开 / 以法代模 / AI 编撰嫌疑）
5. 出现新类型错误（首次出现的失败模式）
6. Yoyo 在任务中显式要求 "校验" / "核对"

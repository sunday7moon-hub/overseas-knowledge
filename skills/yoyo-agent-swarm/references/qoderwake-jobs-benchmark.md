## 一、QoderWake 岗位配置模式拆解（6 步链路）

| 步 | 环节 | QoderWake 做法 | 本质 |
|:--:|---|---|---|
| 1 | **一句话定义岗位** | 用户说"我要一个 XX 岗"（前端/后端/PM/内容运营/数据分析/项目/UI 等 10 预设） | 把「要什么人」压缩成岗位意图 |
| 2 | **生成角色文档三件套** | 自动产出：职责清单 / 协作关系 / 权限边界 | 把意图固化成可执行、可审计的 JD |
| 3 | **权限默认无生产** | 数字员工默认无生产环境权限；高危操作拦截 + 二次授权 | 先划禁区再上岗 |
| 4 | **确认上岗** | 人确认角色文档后激活，7×24 值守 | 人做最后一道录用审批 |
| 5 | **Harness 五维沉淀** | 跑一轮后回写：任务记忆 / 技能库 / 执行策略 / 校验规则 / 工作流，越用越准 | 把"经验"变成"组织资产"而非个人记忆 |
| 6 | **矩阵化运营** | 近 3 个月 10 万数字员工上岗、约 200 万次有效任务；打通钉钉/飞书/企微群聊触发 | 用"团队规模+任务量"对外叙事，抢组织话语权 |

**一句话**：先定义岗位（JD）→ 再给权限（默认无生产）→ 人确认上岗 → 跑一轮沉淀一轮（五维）→ 规模化叙事。**阿里把 Agent 当员工招聘、录用、培训、考核。**

## 三、直接可抄的 5 个动作（按投入排序）

1. **录用审批单** = 岗位说明书（已出 4 份：A15 合规监测员 / A3 早报编辑 / A12 Sourcer / A9 薪酬专员）→ 对外的"我们是一个团队"叙事。
2. **默认无生产权限声明**：每份 registry 卡片加一行「权限边界：默认无生产环境写权限」，高危动作 = 拦截清单。
3. **跑完自动复盘回写**：巴蒂 Step 6 汇报后强制加 3 行复盘（踩了什么坑 / 什么规则要改 / 什么可复用）→ 写当日 memory → 变更则回写对应 SKILL。
4. **合格线先行**：每个 Agent 定义"做到什么算 OK"（产物数量 + 质量门禁 + 谁验收）——QoderWake 上岗标准的本地版。
5. **@ 触发试点**（结构性，放 P1）：先挑 A3（早报）或 A15（校对）试点飞书群 @ 触发，验证"人在环上"体验。

## 四、不抄的部分（保持差异）

- **不抄** 10 岗位大而全预设：15 Agent 已按真实业务域（D1–D7）长出来，比预设更贴地。
- **不抄** 内部先跑→外溢的 To B 叙事：我们是产品运营侧的工具群，对外主体是 Humance 产品而非 Agent 群本身；岗位说明书用于"内部定位 + 售前讲故事"，不上架。
- **QoderWake 教训沿用**：赢了赛马 ≠ 组织主导权 → 岗位说明书 + 能力清单是防"工具无归属"的疫苗，不是 KPI 表演。

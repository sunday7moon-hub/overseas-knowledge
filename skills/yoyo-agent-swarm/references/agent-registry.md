## 0. 设计原则

| 原则 | 说明 |
|------|------|
| **上下文隔离** | 每个 Agent 独占一套「飞书表 + 脚本 + 记忆文件」，禁止跨 Agent 写别人的表 |
| **触发独立** | 每个 Agent 有独立 cron 时间点，互不抢占 |
| **失败隔离** | 单 Agent 失败不影响其他 Agent；失败由 QC Auditor 捕获并通知 Yoyo |
| **幂等可重跑** | 任一 Agent 重复执行同一天，结果应一致（30天/60天去重窗口保证） |
| **宁缺毋滥** | 采集类 Agent 找不到合规来源 → 记 `no_result`，严禁 AI 编撰/以法代模 |
| **只汇报不越权** | 除明确授权外，Agent 不得修改其他 Agent 的配置与自动化 |
| **默认无生产权限** | 全部 Agent **默认无线上生产写权限**（Strapi prod / Anchor DB）；拿到写 Token 也须 Yoyo 在场确认才可写；越界清单见 §0.1 |

**成对协作链**（按顺序，勿跳步）：
1. **文达（需求与验收标准）→ 简一（界面与交互）** —— 两边 README 互指协作边界；文达只出需求，简一不替产品做决策。
2. 专家团内部：**甄准（画像评分）→ 成丹（业务指导）→ 汇编输出**（Phase 1/2/3）。
3. **衡准（架构质量门禁）→ 文达/简一/内部 Agent**：衡准只出评审报告 / 埋点规范 / 整改清单，**不替研发写代码、不替产品改 PRD、不做界面**；需落地时由巴蒂转派 A14/A10/A2/A5，或交文达/简一。
4. **言（内容编排）→ 内部 Agent / 通用内容技能**：言 出内容文案与选题，凡涉及竞品/薪酬/合规事实先加载对应技能取真实数据；需落库 / 对外发布（飞书 / 前端 / 小红书）由巴蒂转派 A1/A2/A3/A13，需海报 / PPT / PDF 等产出形态时调用对应通用内容技能，**不自造工具链、不接 cron**。
5. **阿承（客户群接单）→ 专业专家 → 内部 Agent（如需落库/发布）**：阿承负责客户群内的解码、记录、派单、回执、追踪；专业结论交薪探/成丹/文达/简一，需要跑批落库或对外发布时交巴蒂转派内部 Agent。**阿承是交付链的入口与收口，不是专业结论的出口。**
6. **言（内容编排）→ 阿运（上线把关）→ 巴蒂执行侧（暂存/通知/上线）**：言出内容与标注建议；阿运按三道门禁判「能不能上线」并出复核结论；**实际动手**（本地暂存 → 通知 → 人工确认 → 写线上 → 回读复验）由巴蒂派执行侧跑 `humance-guide-annotation` 的两阶段发布脚本。**阿运只批不写，Yoyo 一句话才算确认。**

**交付约束**：简一交付前必须跑校验三件套，**退出码 0 才算通过**（沙箱无法渲染，静态校验是唯一兜底）。
**回流规则**：专家包产物（PRD / 原型 / 打法）若需进入自动化链路（落飞书表、对外发布、进交付件），由**巴蒂接手转派对应内部 Agent**，专家包本身不写业务表（受 §0.1 越界禁令约束）。
